# 11 训练诊断、消融与检查点选择

## 11.0 评估器也应有固定接口

```text
evaluation_report = evaluate(
    frozen_checkpoint,
    fixed_scenario_suite,
    fixed_metrics,
    fixed_seeds
)
```

输出应是包含分布、极值、失败原因和视频索引的报告，而不是一句“看起来不错”。固定输入集合后，不同 checkpoint 才有可比较意义。

## 11.1 “奖励在涨”只说明策略更会玩这套计分规则

总奖励是必要信号，但它把许多目标压成了一个数。两个策略都得 80 分，可能分别是：

- A：速度跟踪很好，但动作抖、功耗高；
- B：走得平滑省力，但速度误差更大。

所以训练面板至少分四层看：

| 层 | 指标示例 | 回答什么 |
|---|---|---|
| 学习过程 | policy loss、value loss、entropy、KL、学习率 | PPO 更新是否健康 |
| 任务效果 | 三轴速度误差、命令分箱成功率 | 是否真的完成任务 |
| 身体质量 | 姿态、足滑、非足接触、步态、动作变化 | 用什么方式完成 |
| 硬件代理 | 力矩、速度、功率、限位裕量、峰值 | 是否接近可执行边界 |

## 11.2 先看分布，不只看均值

平均误差 `0.1 m/s` 可能来自所有样本都在 `0.1`，也可能是 99% 很好、1% 极端失控。真机更关心后者。

建议报告：

- 中位数、P90、P95、P99、最大值；
- 不同命令区间的条件统计；
- 不同摩擦、质量、扰动和地形下的统计；
- 每种终止原因的次数；
- 连续运行时间和首次失败时间。

## 11.3 视频怎么用才不被骗

视频适合发现指标没有想到的行为，但容易挑最好的一段。规范做法：

1. 固定一组评估种子与命令脚本；
2. 自动录制成功、典型和失败分位，而非人工只挑最好；
3. 视频旁同步显示命令、实际速度、关节/力矩极值和终止原因；
4. 保留失败视频，不在下一轮覆盖。

## 11.4 多随机种子在排除什么

RL 训练包含策略采样、环境随机化和参数初始化。一次成功可能只是幸运。至少用多个种子回答：

- 最终能力是否稳定出现；
- 收敛速度波动多大；
- 某次改动提升的是平均水平还是只救了一个种子；
- 最差种子是否出现新的危险行为。

如果算力有限，可以先用多个短跑筛查，再对少量候选做长跑，但不能把一个幸运 run 当成方法结论。

## 11.5 消融实验是什么

消融就是只拿掉或替换一个关键设计，看能力怎样变化。例如：

```text
完整配置
vs 去掉 5 帧历史
vs 去掉动作变化率惩罚
vs 去掉摩擦随机化
vs critic 不看特权基座线速度
```

它帮助回答“这个设计为什么存在”。若去掉某项完全没影响，可能它确实不必要，也可能当前评估没有覆盖它要解决的场景。

## 11.6 一个实用的实验卡片

每次改动写清：

```text
实验问题：增加延迟随机化能否提高 10~30 ms 时延下的成功率？
唯一主要改动：训练时随机观测延迟 0~30 ms
保持不变：模型、奖励、命令、PPO 配置、评估集
种子：11, 22, 33
主指标：各延迟分箱存活率、跟踪 P95、动作峰值
退化警戒：0 ms 下跟踪误差不得恶化超过批准范围
结论：支持 / 不支持 / 证据不足
```

“感觉更稳”不能替代可复核结论。

## 11.7 怎样选 checkpoint

不要默认最后一个或总奖励最高的 checkpoint 最好。训练后期可能为了某些奖励牺牲平滑性，也可能策略熵降低后丢失恢复能力。

建立固定评估集，对多个 checkpoint 计算：

```text
硬门槛：NaN=0、越限=0、禁止接触=0、安全退出全部触发
任务指标：跟踪误差、成功率、命令覆盖
质量指标：动作变化、姿态、足滑、功率代理
鲁棒指标：随机化、扰动、时延和长时测试
```

先用硬门槛淘汰，再在剩余候选中做多目标选择。不要用一个加权总分掩盖不可接受的单项失败。

## 11.8 何时停止训练

以下任一情况都值得暂停而非盲目加迭代：

- 训练奖励涨，独立评估停滞或下降；
- value loss、KL 或梯度出现异常；
- 策略开始输出饱和动作；
- 能力只在少数命令或环境成立；
- 修改目标已验证，继续训练可能遗忘其他能力；
- 多个种子显示当前设计存在系统性瓶颈。

停止训练不等于项目完成；它意味着该轮实验已经提供足够信息，应进入诊断或冻结评估。
