# 导读：怎样学才不会在中途失去主线

## 1. 你正在造的不是“大脑文件”，而是一条闭环

初学 RL（Reinforcement Learning，强化学习）运控时，很容易把全部注意力放在神经网络上：几层 MLP（Multi-Layer Perceptron，多层感知机）、PPO（Proximal Policy Optimization，一种限制单次更新幅度的强化学习算法）、奖励多少。真机却不认识这些名词。真机只会经历下面的循环：

```text
传感器读数
  ↓ 状态解释、坐标变换、关节重排、缩放、历史缓存
策略观测
  ↓ 神经网络推理
29 个动作数值
  ↓ 缩放、默认姿态、限幅、关节重排
29 个关节目标
  ↓ 低层 PD、电机与真实接触
机器人运动
  └──────────────────→ 新的传感器读数
```

策略只是闭环中的一小段。**可部署**的真正含义，是整条环路在训练、回放、第二仿真器和真机上保持同一种解释。

把这张图翻译成更像程序的写法：

```text
raw_state = sdk.read_state()
command   = command_source.read()
obs       = observation_builder(raw_state, command, last_action, history)
action    = actor(obs)
q_des     = action_processor(action)
motor.send(q_des, dq_des, kp, kd, tau_ff)
```

今后看到任何公式，都要能放回某一行。放不回去，就说明还不知道它解决的是哪个接口问题。

## 2. 每章只抓一个问题

第一次阅读不要同时研究 Isaac Lab 源码、PPO 论文和电机总线。按下面顺序追问即可：

1. 我希望真机做到什么，怎样量化？
2. 策略每 20 ms 能看到什么？
3. 策略输出的 29 个数分别是什么意思？
4. 仿真怎样根据动作走到下一个时刻？
5. 奖励怎样告诉策略“这种未来更好”？
6. 怎样证明它不是钻仿真的空子？
7. 怎样保证部署程序没有把同一个数解释成另一件事？

只要这七个问题没有断，暂时看不懂 PPO 的某个公式也不会丢掉全局。

## 3. 两条必须始终分清的数据

### “机器人现在怎样”

来自传感器与状态处理，例如关节反馈 `q、dq`、IMU 角速度和投影重力。它们描述现实。

### “希望机器人怎样”

来自上层接口，例如：

```text
[vx_cmd, vy_cmd, vyaw_cmd]
```

分别表示希望前后、左右和绕竖直轴旋转多快。它们描述目标。策略必须同时看到“现在”和“希望”，才能在同一个身体状态下知道这次应该站住、前进还是转弯。

## 4. 三种阅读深度

每章都可以分三遍读：

- 第一遍只看“本章解决什么”和章末检查题，先建立因果关系；
- 第二遍亲手算维度、单位和频率，并运行实践代码；
- 第三遍才进入 Isaac Lab、RSL-RL 和部署 C++ 源码核对实现。

不要把“暂时看不懂框架代码”误认为“不懂 RL 运控”。先能说清现实对象，再学习框架怎样表达它。

遇到本章没有当场解释的英文词，可以查[附录 C：训练与部署词语表](附录C-训练与部署词语表.md)。词语表只负责救急，主线仍会在概念真正发挥作用时解释“为什么需要它”。

## 5. 本教程中的固定案例

为了避免每章换机器人，我们固定使用同一个案例：

```text
机器人：G1 风格 29 自由度人形
任务：根据 (前向速度, 横向速度, 转向角速度) 命令运动
策略输入：本体感觉、命令、关节状态、上一步动作、5 帧历史
策略输出：29 个归一化关节位置增量
执行方式：默认关节姿态 + 0.25 × 策略动作 → 低层 PD
仿真周期：5 ms
策略周期：20 ms，即 50 Hz
训练算法：RSL-RL 的 PPO
导出格式：ONNX + 部署配置
复核路径：Isaac Lab play → MuJoCo Sim2Sim → 分级真机测试
```

这些数字用于把概念钉在具体对象上。以后更换机器人时，方法不变，但维数、顺序、比例、增益和安全阈值必须重新生成并验证。

## 6. 建议的实践节奏

不要一上来就让 29 自由度人形学走路。更稳妥的学习顺序是：

```text
先运行本仓库的部署契约测试
→ 能手算观测 96 × 5 = 480
→ 能手算动作如何变成关节目标
→ 在官方任务中只 play 已有策略
→ 训练短跑验证数据流
→ 建立站立基线
→ 加小范围前进命令
→ 加横移、转向和扰动
→ 冻结候选模型并做 Sim2Sim
→ 最后才进入真机分级测试
```

这不是绕远路。越早发现维度、单位、顺序和周期错误，越少把 GPU 时间浪费在一个从定义上就无法部署的实验上。
