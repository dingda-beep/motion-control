# 训练实验手册：从两次迭代短跑到发布候选

这份手册要培养的不是“能复制一条长训练命令”，而是每走一步都知道自己刚排除了什么错误。

命令与路径按 Unitree RL Lab 参考提交 `4960b84` 编写。上游项目更新后，先核对官方 README 和参数帮助：

```bash
# 只查看当前安装版本真实支持的参数，不会开始训练或推理。
python scripts/rsl_rl/train.py --help
python scripts/rsl_rl/play.py --help
```

### 操作

# 记录代码身份和未提交修改；以后才能知道 checkpoint 由哪份代码产生。

按照[官方安装说明](https://github.com/unitreerobotics/unitree_rl_lab)安装匹配版本的 Isaac Sim、Isaac Lab、机器人资源和项目扩展，然后：

```bash
# 列出已经注册成功的任务；这里只做安装冒烟检查，不会训练策略。
./unitree_rl_lab.sh -l
```

- 能否列出 `Unitree-G1-29dof-Velocity`？
- 机器人资源来自哪一个 commit 或文件哈希？

## 实验 1：先 play，学会读一条闭环

若当前官方版本提供兼容的预训练 checkpoint，先加载它；否则使用官方发布方式取得明确版本的 checkpoint。运行：

```bash
# 加载已有 checkpoint 做确定性推理，先观察闭环与导出文件。
./unitree_rl_lab.sh -p --task Unitree-G1-29dof-Velocity
```

不要只看“会走”。逐项记录：

```text
命令从哪里显示或输入
一个策略步多长
策略输入/输出维度
零命令是否站稳
从走到停是否平滑
哪些事件会终止环境
play 时导出了哪些文件
```

然后打开本次 run 的 `params/env.yaml`、`params/agent.yaml` 和 `params/deploy.yaml`，把屏幕行为与配置字段连起来。

## 实验 2：两次迭代的训练短跑

先用少量环境与迭代验证管线：

```bash
# 这是数据管线短测，不以学会走路为目标。
# --headless：关闭渲染，验证无界面训练路径。
# --task：选择本教程贯穿的 G1 速度任务。
# --num_envs：少量并行环境，先降低启动和排错成本。
# --max_iterations：只更新两轮，检查 rollout、日志和保存。
# --seed：固定随机性，便于复现这次短跑。
# --run_name：给输出目录一个可追踪的实验名。
python scripts/rsl_rl/train.py \
  --headless \
  --task Unitree-G1-29dof-Velocity \
  --num_envs 64 \
  --max_iterations 2 \
  --seed 42 \
  --run_name smoke_seed42
```

当前算法每环境每轮采 24 步，所以每轮是：

\[
64\times24=1536\text{ 条转移}
\]

两轮约收集 3072 条转移。它不可能证明学会走路，只检查：

- 环境、训练器和 GPU 管线能运行；
- 观测、奖励、损失没有 NaN/Inf；
- resolved config 和 `deploy.yaml` 被保存；
- 日志目录带有 seed 与 run 名；
- 短跑结束后可以定位实际输出文件。

如果短跑失败，先修管线，不能通过增加到 4096 环境和 50000 迭代治疗。

## 实验 4：建立“站立版”任务分支

不要直接覆盖官方基线。创建独立 Git 分支和新的任务/配置名，例如：

```text
Unitree-MyRobot-Stand-v0
```

第一版只做：

```text
平地
零速度命令
较小的关节初始偏差
暂时关闭周期推扰
暂时缩窄质量和摩擦随机化
20 秒回合
```

奖励从可解释最小集合开始：

- 身体保持合理朝向和高度；
- 禁止非足部接触；
- 关节不越限；
- 动作不要每步剧烈变化；
- 在有效状态中存活。

### 先不要做

- 不要为了“像走路”保留强制交替步态奖励；
- 不要同时复制所有复杂地形和推力；
- 不要只看总奖励；
- 不要在模型方向、默认姿态和 PD 尚未验证时调几十个权重。

### 站立验收

固定多个初始偏差和随机种子，统计 20 秒成功率、姿态、高度、非足接触、动作差分和关节/力矩极值。零命令时持续踏步不算理想站立。

## 实验 5：第一次让它向前

从站立配置复制出新任务，只增加一个主要难度：

```text
v_x 命令：零附近到小正速度
v_y = 0
ω_z = 0
```

加入前向速度跟踪后，观察三种失败：

### 不肯走

画出跟踪奖励、存活奖励、动作/能耗/姿态惩罚的每步贡献。可能是移动收益被代价淹没，也可能探索与动作尺度不足。

### 冲一下就摔

检查命令是否过大、初始课程是否太难、终止与姿态信号是否合理，以及动作是否迅速饱和。

### 速度对但在滑或蹭地

用足部速度、接触位置、非足接触和视频证明具体歪方法，再加入对应信号。不要因为“不好看”一次加十个奖励。

每个假设至少做基线与改动版对照，并使用多个种子。

## 实验 6：扩到统一速度策略

能力按下面顺序扩展：

```text
零命令站立与走停
→ 前进范围扩大
→ 后退
→ 横移
→ 转向
→ 组合命令
```

每扩一项，评估矩阵保留旧项。这样能发现灾难性遗忘或奖励冲突，而不是只庆祝新动作出现。

当前官方 G1 示例起始范围约为三轴 `[-0.1, 0.1]`，课程上限分别为：

```text
v_x: [-0.5, 1.0] m/s
v_y: [-0.3, 0.3] m/s
ω_z: [-0.2, 0.2] rad/s
```

这些是参考任务的数字，不是新机器人的默认答案。新机器人范围由机械能力、低层接口和分级测试决定。

## 实验 7：有证据地加随机化

创建实验矩阵，每次增加一种主要变化：

| 实验 | 新增随机化 | 主评估 |
|---|---|---|
| R0 | 无/很窄 | 名义模型能力 |
| R1 | 摩擦 | 各摩擦分箱成功率、足滑 |
| R2 | 质量/质心 | 各载荷分箱跟踪与姿态 |
| R3 | 执行器/PD | 动作、力矩、恢复 |
| R4 | 观测噪声/偏置 | 状态误差下稳定性 |
| R5 | 延迟/抖动 | 各时延分箱成功率与峰值 |
| R6 | 外力扰动 | 方向×大小恢复率 |

每项范围写明来源。若只写“±20%”，却不知道 20% 对应什么真机证据，随机化无法形成可信部署包络。

## 实验 8：多种子长跑与 checkpoint 选择

正式训练命令只是在短跑基础上增加环境与迭代；具体数值要根据 GPU、吞吐和收敛证据决定。例如命令结构为：

```bash
# 命令结构与短跑相同；尖括号内容必须来自吞吐测试和实验预算，不能原样复制。
# --num_envs：并行数受 GPU 显存和仿真吞吐限制。
# --max_iterations：迭代数不是单台机器人走的步数。
# --seed：每个随机种子形成独立 run。
# --run_name：名称应能追到假设和配置。
python scripts/rsl_rl/train.py \
  --headless \
  --task Unitree-MyRobot-Velocity-v0 \
  --num_envs <经过吞吐测试的环境数> \
  --max_iterations <实验预算> \
  --seed <seed> \
  --run_name <唯一实验名>
```

对多个 checkpoint 跑相同评估集。先用 NaN、越限、禁止接触和安全退出等硬门槛淘汰，再比较跟踪、姿态、动作、功率代理、鲁棒性和长时结果。不要自动选择最后一个或总奖励最高的文件。

## 实验 9：导出与三组黄金测试

使用明确 checkpoint 运行 play/export：

```bash
# 明确指定任务和冻结 checkpoint；不要让 play 自动猜“最新模型”。
# --task：必须与训练时的任务接口一致。
# --checkpoint：使用绝对路径锁定候选参数。
python scripts/rsl_rl/play.py \
  --task Unitree-MyRobot-Velocity-v0 \
  --checkpoint /absolute/path/to/model_N.pt
```

确认生成 ONNX/JIT 和部署配置，然后做：

1. 同一网络输入下 PyTorch 与 ONNX 动作一致；
2. 同一原始状态下训练与部署观测一致；
3. 同一 actor 动作下最终电机目标一致。

模型文件、契约、resolved config 和黄金向量共同进入发布候选目录。

## 实验 10：Sim2Sim 与真机闸门

先在 MuJoCo 或另一独立物理实现中保持模型与契约冻结，按推理、观测、动作、执行器、接触逐层排错。通过后，按教程第 16 章从完全离线、只读状态、支撑下单元测试、策略接管到小范围落地逐级推进。

任何一级失败，都先保留日志并退回能复现问题的最低层。不要在真机通电现场临时改 scale、PD、映射或滤波然后继续试。

## 这十个实验真正训练的是什么

表面上，你在训练神经网络；实际上，你也在训练自己的工程判断：

```text
看到现象
→ 找到可测证据
→ 提出单一假设
→ 只改一个主要因素
→ 多种子和固定评估验证
→ 把结论固化进契约、测试或安全边界
```

能稳定重复这条循环，才有机会面对一台全新机器人，一步一步得到可部署候选，而不是靠复制参数碰运气。
