# 04 一个控制周期

## 4.0 一个周期就是一个反复调用的函数

```text
motor_packet, next_memory = control_tick(
    latest_robot_state,
    velocity_command,
    previous_action,
    observation_history,
    policy_model,
    policy_contract
)
```

输入必须带时间戳；输出不仅有本周期电机目标，还会更新 `last_action` 和历史缓存，供下一周期使用。20 ms 指这个函数应按 50 Hz 反复完成，不是只调用一次。

## 4.1 机器人不是“网络算一次就走一步”

本案例有三种容易混淆的时间尺度：

```text
物理仿真步：5 ms
策略更新步：20 ms
一次策略步内的物理子步数：4
```

关系是：

\[
\Delta t_{policy}=\Delta t_{physics}\times decimation
=0.005\times4=0.02\;s
\]

因此策略频率是：

\[
f_{policy}=1/0.02=50\;Hz
\]

`decimation=4` 的意思不是丢掉四帧数据，而是一个策略动作在四个更细的物理步中被保持或执行，然后策略再看新状态。

## 4.2 一个 20 ms 周期里发生什么

```text
t = 0 ms     读取状态，检查时间戳
             构造并缩放观测，更新历史缓存
             ONNX 推理得到 action
             动作缩放、加默认姿态、限幅、关节映射

t = 0~20 ms  低层 PD 持续根据目标和最新关节状态产生力矩

t = 20 ms    再次构造观测并推理
```

真机低层 PD 或驱动内部环通常可能比 50 Hz 更快。不要把“策略 50 Hz”误解为“电机每 20 ms 才控制一次”。策略给的是较慢更新的协调目标，低层环负责更快地追踪它。

## 4.3 为什么频率也是策略的一部分

假设同一串动作在训练时每 20 ms 更新，部署时却每 10 ms 更新。现实一秒内动作变化次数翻倍；速度、加速度、PD 误差演化和接触时机都会改变。

更隐蔽的是历史观测。本案例保存 5 帧：

- 50 Hz 时覆盖约 100 ms 的离散片段；
- 100 Hz 时只覆盖约 50 ms。

维度仍然是 480，网络却看到了一段时间尺度完全不同的“短片”。因此频率错配不是性能小差异，而是输入语义改变。

## 4.4 延迟不只是“慢一点”

真实闭环包含：

```text
传感器采样延迟
+ 通信延迟
+ 状态处理时间
+ 推理时间
+ 命令发送延迟
+ 驱动执行延迟
```

如果总延迟为 30 ms，策略在时刻 \(t\) 做决定时，看到的可能是 \(t-30\text{ ms}\) 左右的身体。人形在这段时间内已经继续下落或转动，所以旧状态可能让纠正动作来得太晚。

训练中可加入延迟随机化，但部署端仍必须监测时间戳。随机化用于提高容忍度，不是允许无限陈旧数据。

## 4.5 截止时间与抖动

50 Hz 意味着每 20 ms 需要一个新动作。推理平均耗时 2 ms 并不充分，还要看最坏情况：

```text
平均 2 ms，偶尔 45 ms
```

偶发超时可能比稳定的 5 ms 更危险。应记录：

- 平均推理时延；
- P95、P99 和最大时延；
- 控制周期抖动；
- 连续错过 deadline 的次数；
- 状态数据年龄；
- 超时后的明确动作：保持、缓降、切换安全姿态或退出。

具体回退策略依赖硬件安全设计，不能由教程替现场团队统一决定，但绝不能是“无限复用最后一个动作”。

## 4.6 本章手算

若物理步长改为 `0.0025 s`，仍希望策略保持 50 Hz，`decimation` 应为多少？

\[
decimation=0.02/0.0025=8
\]

如果只改物理步长而忘记改 decimation，策略频率会变成 100 Hz，训练任务已经发生变化。
