# 01 任务定义与安全边界

## 1.0 先定义准备交给别人调用的能力

```text
joint_targets = locomotion_controller(
    robot_feedback,
    velocity_command
)
```

输入中的 `robot_feedback` 描述机器人现在怎样，`velocity_command` 描述调用者希望怎样；输出是低层能够执行的关节目标。任务定义要说明这个函数在哪些机器人状态、命令和环境范围内有效，超出后由谁拒绝或退出。

## 1.1 不要先问“奖励怎么写”

先写一句没有算法名的任务定义：

> 在平整或轻微起伏地面上，G1 根据三维速度命令持续站立、前进、后退、横移和转向；在规定的命令、状态、时延和接触范围内保持稳定，并且动作不超过关节和执行器安全边界。

这里已经包含五件事：

1. **对象**：哪台机器人、多少关节、什么执行器；
2. **命令**：人或上层规划器怎样表达意图；
3. **环境**：平地还是台阶，摩擦和扰动范围多大；
4. **成功**：速度误差、稳定时间、能耗、足滑等怎样测量；
5. **边界**：训练和验收覆盖到哪里，超出后怎样退出。

如果这句话含糊，奖励函数只会把含糊放大。

## 1.2 RL 究竟负责哪一段

在本项目里，RL 策略负责：

```text
根据最近的身体状态和速度命令
→ 每 20 ms 产生一组协调的关节位置增量
```

它不负责：

- 从 IMU 原始电压标定姿态；
- 发现通信断开并切断电机；
- 保证目标永远不越过硬件极限；
- 管理上电、起立、运行、退出和急停状态；
- 规划穿过房间的全局路线；
- 替代电机驱动器内部的快速电流环。

这些事情仍由状态估计、命令管理、限幅器、低层控制器、实时程序和安全状态机承担。RL 很强，但强的是在复杂连续状态下学习协调动作，不是自动吞掉整套机器人软件。

## 1.3 站、走、跑需要每个动作一个模型吗

不一定。本项目给策略一个连续命令：

```text
c = [v_x^cmd, v_y^cmd, ω_z^cmd]
```

其中：

- `v_x^cmd`：希望前后多快，单位 m/s；
- `v_y^cmd`：希望左右多快，单位 m/s；
- `ω_z^cmd`：希望绕竖直轴转多快，单位 rad/s。

零命令附近对应站立，正负前向命令对应前进和后退，横向命令对应横移，角速度命令对应转向。只要训练分布覆盖这些命令，一个网络就能学会混合技能。

但“能用一个模型”不等于“所有动作都应该塞进一个模型”。高速跑、跳跃、舞蹈和强操作若具有冲突的状态分布、奖励或安全边界，可能需要分阶段训练、教师—学生蒸馏、条件策略或上层技能切换。判断标准是任务分布是否能被一个策略稳定覆盖，而不是追求模型数量越少越先进。

## 1.4 先写验收表

下面是一份教学用草案，不是真机认证值：

| 指标 | 候选标准 | 为什么需要 |
|---|---:|---|
| 平地存活率 | 1000 个回合中 ≥ 99% | 先排除基本稳定性问题 |
| 前向速度均方根误差 | ≤ 0.15 m/s | 奖励高不等于命令跟得准 |
| 横滚/俯仰最大值 | 在规定阈值内 | 限定姿态安全包络 |
| 关节限位越界 | 0 次 | 防止策略靠撞限位完成任务 |
| 非足部碰撞 | 0 次 | 膝、手或躯干撑地不算会走 |
| 状态超时退出 | 100% 触发 | 通信故障时不能继续盲跑 |
| ONNX 动作误差 | 相对训练端足够小 | 证明导出没有改变策略 |

真正项目要把“规定阈值”替换为硬件团队、场地和任务共同批准的数字。

## 1.5 安全不能只写成负奖励

给“关节越限”一个很大的负奖励，并不能保证它永远不越限。原因很简单：奖励是优化偏好，不是硬约束；策略还可能遇到训练之外的状态。

因此同一个安全目标通常需要多层保护：

```text
训练：越限惩罚 + 越限终止
动作处理：位置、增量、速度、力矩限幅
部署：状态新鲜度、姿态和数值合法性检查
驱动：硬件允许范围与故障保护
现场：支撑、净空、物理急停和操作流程
```

## 1.6 本章动手任务

在训练前写一页 `task_card.md`，至少回答：

1. 谁产生速度命令？命令多久不更新算失联？
2. 策略输出的位置增量相对于哪个默认姿态？
3. 机器人在哪些地面、载荷和速度范围内被声明为可用？
4. 哪些事件只扣奖励，哪些事件必须终止，哪些必须由部署程序硬退出？
5. 选模型时看哪些指标，不能只看哪个数？
