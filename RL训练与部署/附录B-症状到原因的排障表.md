# 附录 B：症状到原因的排障表

先排语义和软件，再排动力学；先做开环小测试，再做全身闭环。不要看到机器人倒了就立刻重新调奖励。

| 症状 | 第一批检查 | 第二批检查 |
|---|---|---|
| 策略加载后立即猛跳 | 关节映射、默认姿态、动作比例、弧度/角度、Kp/Kd | 历史初始化、ONNX 输出、模式冲突 |
| 输出出现 NaN | 原始状态、四元数、除零、normalizer、历史缓冲 | 网络导出、数值精度、异常输入分布 |
| 原地能站，给命令就倒 | 命令顺序/坐标系/范围、训练是否覆盖 | 跟踪奖励、命令变化率、动作饱和 |
| 零命令仍踏步 | 零命令采样比例、站立验收、命令死区 | 步态奖励是否无条件生效 |
| 只向左或右倒 | 左右映射、符号、默认姿态、IMU 轴 | 质量/接触不对称、训练数据偏置 |
| 步态频率不对 | policy dt、decimation、部署循环 | 历史时间跨度、命令更新周期 |
| 仿真稳定，真机高频抖 | PD/执行器、周期抖动、噪声、动作变化率 | 柔性、延迟、未建模共振 |
| Isaac Lab 好，MuJoCo 滑 | 足底碰撞体、摩擦、接触参数 | 策略利用求解器、随机化不足 |
| ONNX 与 PyTorch 不同 | normalizer、模型输入名/形状、推理模式 | 不支持算子、精度和导出版本 |
| 动作相同，电机目标不同 | scale、offset、clip、joint map | rate limit 与处理顺序 |
| 运行几秒后发散 | 历史缓存滚动、状态时间戳、估计漂移 | 温度/限流、接触与延迟累积 |
| 训练奖励高但频繁摔 | 奖励贡献、终止统计、评估分布 | 奖励漏洞、checkpoint 选择 |
| 增加随机化后什么都学不会 | 范围过宽、同时改变太多、课程顺序 | 网络容量、优化与可观测性 |
| 扰动后不恢复 | 初始/扰动状态覆盖、终止是否过早 | 历史、特权 critic、恢复奖励 |
| 训练越来越慢 | 仿真吞吐、GPU/CPU、日志和渲染 | 接触对数量、环境数、内存 |
| 真机命令偶发停顿 | deadline、状态/命令年龄、日志阻塞 | 调度、总线、CPU 亲和与内存分配 |

## 最小排障记录

每次问题至少保存：

```text
模型与契约哈希
原始状态和时间戳
构造后的完整观测
actor 原始动作
裁剪/缩放/映射后的目标
关节反馈和力矩/电流状态
命令
状态机事件
控制周期耗时
同步视频
```

没有这些证据，“可能是 Sim2Real”只是无法行动的猜测。
