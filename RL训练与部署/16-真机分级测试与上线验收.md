# 16 真机分级测试与上线验收

## 16.0 每一级都是一个带闸门的函数

```text
evidence, go_or_no_go = run_test_level(
    frozen_release,
    approved_test_plan,
    previous_level_evidence,
    safety_setup
)
```

输出 `NO-GO` 时不能靠现场口头判断跳级。只有证据满足当前级出口条件，发布候选才能成为下一级的输入。

## 16.1 原则：一次只增加一种真实风险

从仿真直接跳到无支撑高速行走，会同时引入硬件、通信、状态估计、执行器、接触和人员风险。出错时既难归因，也难止损。

分级测试的目的，是让每一级只回答有限问题；未通过就停在当前级修正，不靠下一级“也许会好”。

## 16.2 Level 0：完全离线

不连接电机，只做：

- 模型和契约 schema、哈希、机器人型号检查；
- 固定向量的训练端—ONNX—部署端等价性；
- 录制真机状态回放，构造观测并推理但不发送；
- NaN、Inf、越界、旧时间戳、乱序包注入；
- 推理时延和控制周期压力测试；
- 故障状态转换单元测试。

目标：证明软件面对坏数据会拒绝，而不是产生电机命令。

## 16.3 Level 1：通信接通，执行禁止

读取真实 IMU、编码器和状态时间戳，部署程序完整运行，但输出被隔离或电机不使能。

检查：

- 29 个关节的名字、索引、方向、零位；
- 静止时投影重力和角速度是否合理；
- 观测数值范围与仿真评估分布是否重叠；
- 摇杆/上层命令的死区、范围和超时；
- 日志是否足以还原一次周期。

## 16.4 Level 2：可靠支撑下的低层单元测试

在符合厂家与现场规范的机械支撑下，不运行全身 RL，逐项验证：

- 关节小幅目标的方向和幅度；
- 默认姿态与插值过程；
- PD 模式、增益、力矩/速度限制；
- 急停、失联、姿态异常和程序崩溃后的行为；
- 机载控制与自定义控制之间不存在命令冲突。

任何关节映射或方向疑问都必须在这里解决。

## 16.5 Level 3：支撑下策略接管

让策略在严格限制的命令和动作范围内接管，先用零命令，观察：

- 接管瞬间目标是否跳变；
- 动作是否处于仿真分布；
- 历史缓存初始化是否导致前几帧异常；
- 周期、时延和状态年龄是否达标；
- 策略退出能否回到预期安全状态。

此级主要验证闭环接口，不以“吊着走得好看”为目标。

## 16.6 Level 4：受控落地与小包络

只有前级通过后，才在足够净空、支撑/保护、物理急停和明确人员分工下进入落地测试。按批准计划逐步扩大：

```text
零命令站立
→ 很小前向命令
→ 停止与重新启动
→ 小横移和小转向
→ 更长持续时间
→ 轻微、可控扰动
```

每一步都设停止条件，不在现场临时兴奋地加速或尝试训练外动作。

## 16.7 Level 5：扩大包络

根据前级日志更新模型差异与风险评估，再逐项扩展速度、地面、载荷、持续时间和扰动。每次扩展都形成新评估矩阵；“曾在一种平地走通”不能推广到所有场景。

## 16.8 Go / No-Go 清单

### 必须满足

- 模型、契约、代码、机器人版本和哈希一致；
- 观测和动作 golden test 通过；
- 所有硬门槛指标通过；
- Sim2Sim 和长时测试通过批准标准；
- 急停、通信超时、姿态保护和回退已实测；
- 现场支撑、净空、防护和角色分工就绪；
- 本次测试命令包络已锁定；
- 日志、录像和时间同步已就绪。

### 任一出现即停止

- 不明原因动作跳变或关节映射疑问；
- NaN/Inf、状态陈旧或连续 deadline miss；
- 电机/驱动异常、温度或电流接近限制；
- 实测状态明显超出训练/评估分布；
- 安全回退没有按预期发生；
- 人员、场地或急停条件发生变化。

## 16.9 失败后的正确动作

失败不是“再试一次看看”。保存模型版本、全部状态与命令、动作处理前后数据、状态机事件、时间戳、视频和现场说明。先在离线回放或仿真中复现，再决定属于：

```text
接口错误
状态估计错误
执行器/参数差异
接触差异
训练分布缺口
奖励漏洞
安全逻辑错误
```

修正后产生新候选版本，从受影响的最低测试级重新开始。
