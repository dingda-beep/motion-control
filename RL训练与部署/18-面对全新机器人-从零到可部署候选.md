# 18 面对全新机器人：从零到可部署候选

这一章假设你拿到一台从未做过 RL 运控的新机器人。不是把 G1 配置里的名字替换掉，而是从现实对象重新建立整条因果链。

## 18.0 先写新机器人的接口

第一张纸不要写 PPO 参数，而要先写目标接口：

```text
输入：这台机器人实际能稳定提供的反馈 + 上层真正需要的命令
输出：这台机器人低层真正能稳定执行的命令
边界：输入输出在哪些范围、频率和故障条件下有效
```

之后所有建模、奖励、训练和部署工作，都服务于把这个接口闭环实现出来。

## 18.1 第零步：先判断它是否适合这个任务

确认：

- 关节是否可读取位置、速度和故障状态；
- 低层是否允许稳定的位置/速度/力矩接口；
- 控制命令频率、网络与计算资源能否满足；
- IMU 与必要状态估计是否可用；
- 电机持续/峰值能力、热限制和机械限位；
- 是否具备可靠支撑、急停、净空和测试人员；
- 厂家接口是否允许关闭或切换原有控制，怎样安全完成。

如果连非学习的单关节目标都不能可靠执行，先解决底层系统，不能指望 PPO 修复通信或电机问题。

## 18.2 第一阶段：让模型和真机说同一种关节语言

### 建立机器人模型

从机械资料、URDF/USD 和实测整理：

```text
连杆质量、质心、惯量
关节连接、轴、方向、零位、限位
碰撞几何和足底形状
电机力矩/速度能力
传动、摩擦和低层控制
```

### 做非 RL 体检

在单关节和可靠支撑条件下比较仿真与真机：

```text
给同一小幅阶跃或正弦关节目标
→ 比较位置、速度、超调、稳定时间和力矩响应
```

这不是要求完全拟合，而是先排除方向、单位、零位、增益和数量级错误。

### 阶段出口

- 所有关节映射为双射；
- 零动作对应批准默认姿态；
- PD 小信号响应方向正确、量级合理；
- 模型自由落体、接触和基本静态承重没有明显异常。

## 18.3 第二阶段：先设计部署接口，再创建 RL 环境

从真机可获得的信号定义 actor 观测。若真机拿不到可靠基座线速度，就不要因为仿真方便而塞给 actor；可以给 critic，也可以让 actor 用 IMU、关节和历史间接适应。

选择动作接口时问：

- 真机最低层稳定开放的是什么；
- 该接口的实际更新频率是多少；
- 缩放、默认值、限幅和变化率怎样定义；
- 训练与部署能否执行同一处理顺序。

此时就生成第一版 `policy_contract`，即使网络还没训练。它会暴露“部署端根本无法构造这个观测”之类的设计错误。

## 18.4 第三阶段：建立站立基线

环境先保持简单：平地、零命令、较小初始扰动、少量或不加参数随机化。

目标不是得到漂亮人形步态，而是验证：

1. 仿真模型在默认姿态附近可控；
2. 观测和动作闭环正确；
3. 终止能识别真实摔倒；
4. 奖励能区分直立与错误支撑；
5. 策略不会靠撞限位、蹭地或极高力矩存活。

如果这一步失败，暂停。行走奖励不会自动治好错误惯量、反向关节或过硬 PD。

## 18.5 第四阶段：只加入小范围前进

把前向命令限制在零附近到一个小正速度。观察三类结果：

- 不走：任务收益不足、动作代价过强或探索没有产生有效步态；
- 冲出去后摔：跟踪收益过强、稳定/接触信号不足，或课程太难；
- 速度接近但方式错误：根据足滑、接触、姿态和动作证据修正。

每次只改一个主要因素，多种子对照。第一个能走的模型只是调试工具，不是部署候选。

## 18.6 第五阶段：扩展命令和行为质量

按能力逐步加入：

```text
零命令静止与走停切换
→ 更宽前进、后退
→ 横移
→ 转向
→ 组合命令
```

每扩一维，都保留旧命令评估，防止学会横移却遗忘站立。奖励项随观察到的失败逐步生长，不复制不明来源的权重。

## 18.7 第六阶段：用实测证据加入鲁棒性

先采集真机或台架数据，估计：

- 控制周期和状态年龄分布；
- 关节响应、增益和摩擦差异；
- 质量与载荷范围；
- 常见地面摩擦；
- IMU/编码器噪声和偏置。

再逐项加入随机化与扰动，用分箱评估检查最差条件。若加了某项随机化却没有对应评估，你并不知道它是否真正提供了能力。

## 18.8 第七阶段：建立自己的第二实现

不一定非要 MuJoCo，但至少需要一种独立性：另一物理引擎、另一观测实现、另一推理运行时或由不同代码路径生成的 golden test。

按层验证：网络、观测、动作、执行器、接触。能在第二引擎走路不是终点，无法解释差异也不能进入真机。

## 18.9 第八阶段：冻结候选，不边部署边调参

固定：

```text
actor + normalizer
policy contract
训练配置和代码版本
机器人模型版本
评估报告
哈希与回退版本
```

在部署端临时改动作比例、PD 或观测滤波都等于产生新系统，必须回到受影响的测试层重新验证。

## 18.10 第九阶段：分级进入真机

严格按照：

```text
离线回放
→ 只读真实状态
→ 支撑下非 RL 单关节/默认姿态
→ 支撑下策略零命令接管
→ 受控落地站立
→ 小命令
→ 扩大已验证包络
```

每一级有进入条件、停止条件、日志和批准人。现场观察到异常时退回诊断，不在机器人通电状态下即兴改参数。

## 18.11 一份现实的首轮项目排期逻辑

不能只按“训练需要几天”估算。实际工作量通常分布在：

| 工作 | 它消灭的风险 |
|---|---|
| 模型与接口体检 | 训练在错误机器人上优化 |
| 契约和自动测试 | 训练、部署语义错位 |
| 基线与奖励迭代 | 奖励漏洞和不可解释行为 |
| 鲁棒化与多种子 | 偶然成功和仿真过拟合 |
| 导出、Sim2Sim | 运行时与物理实现依赖 |
| 真机状态机和分级测试 | 软件故障直接变成机械风险 |

GPU 长跑只是其中一项，往往不是最需要耐心的部分。

## 18.12 什么时候才算“训练出可部署模型”

不是第一次站起来，不是视频里走了十秒，也不是总奖励创新高。应当同时满足：

1. 能力在固定、多种子、长时和边界评估中成立；
2. actor 的每个输入输出在真机上有唯一、可测试的解释；
3. 导出与部署运行时等价；
4. 第二实现没有暴露未解释的致命差异；
5. 安全状态机能在策略之外拒绝坏状态和坏时序；
6. 真机只在分级验证过的包络内声明能力；
7. 任何人能根据版本与证据复现它来自哪次实验。

这时更准确的称呼仍是“**可部署候选**”。真正的可用范围，最终由逐级真机证据确定。
