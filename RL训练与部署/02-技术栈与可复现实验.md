# 02 技术栈与可复现实验

## 2.0 先看每个软件吃什么、吐什么

```text
机器人模型 + 任务配置 ──→ Isaac Lab 环境
环境产生的 rollout      ──→ RSL-RL / PPO ──→ checkpoint
checkpoint + 训练配置   ──→ 导出程序 ──→ ONNX + deploy config
冻结发布包              ──→ MuJoCo / 真机部署程序
```

这样看，软件名只是流水线中的实现。真正不能断的是文件和张量接口：上一段输出什么，下一段必须按同一含义读取什么。

## 2.1 为什么选这一套

本教程采用下面的分工：

```text
Isaac Lab       批量创建机器人、推进物理、组织观测/动作/奖励/事件
RSL-RL          用 PPO 收集 rollout、估计优势、更新 actor 和 critic
Unitree RL Lab  提供 G1 任务、机器人配置、训练入口和部署示例
ONNX Runtime    在训练框架之外执行冻结策略
MuJoCo          用不同物理实现做 Sim2Sim
Unitree SDK2    真机状态与低层命令接口
```

选择它不是因为它是唯一答案，而是因为同一官方项目给出了训练、play、Sim2Sim 和 Sim2Real 的连续路径，适合学习完整链路。

## 2.2 先固定版本，再谈复现

“我用 Isaac Lab 训练的”不是完整环境说明。框架 API、默认参数和模型资源都会变化。每次正式实验至少记录：

```text
日期
操作系统与驱动版本
GPU 型号
Python 版本
Isaac Sim / Isaac Lab 版本
Unitree RL Lab Git commit
RSL-RL Git commit 或安装版本
机器人 USD/URDF 资源版本与哈希
任务配置文件哈希
随机种子
完整启动命令
```

教程核对的官方参考快照为：

```text
Unitree RL Lab commit: 4960b84
官方 README 标注: Isaac Sim 5.1.0, Isaac Lab 2.3.0
```

这是阅读锚点，不代表未来必须永远安装这些版本。升级时应重新跑回归测试，不应默默混用新框架和旧模型。

## 2.3 官方项目的基本路径

下面命令来自当前官方 Unitree RL Lab 工作流，执行前应以该项目 README 为准：

```bash
# 安装项目扩展
./unitree_rl_lab.sh -i

# 列出任务，确认安装成功
./unitree_rl_lab.sh -l

# 训练 G1 29 自由度速度策略
./unitree_rl_lab.sh -t --task Unitree-G1-29dof-Velocity

# 加载策略进行可视化推理
./unitree_rl_lab.sh -p --task Unitree-G1-29dof-Velocity
```

等价的训练入口是：

```bash
# 直接入口与上面的 -t 包装脚本作用相同；下面两项分别控制显示和任务注册名。
# --headless：不渲染训练窗口，把算力留给并行仿真。
# --task：选择 G1 29 自由度速度任务。
python scripts/rsl_rl/train.py \
  --headless \
  --task Unitree-G1-29dof-Velocity
```

不要急着跑几万次迭代。第一次只做“短跑体检”：减少环境数和最大迭代数，确认仿真能够启动、观测没有 NaN、回报能记录、checkpoint 能保存、play 能加载。短跑成功证明数据管线通了，不证明策略已经学会。

## 2.4 三类配置不要混在一起

### 机器人配置

描述身体和执行器：连杆质量、惯量、关节、限位、默认姿态、力矩和速度上限、仿真执行器参数。

### 任务配置

描述学习世界：观测、动作、命令、奖励、终止、重置、地形、随机化、并行环境数和控制周期。

### 算法配置

描述怎样学习：网络宽度、激活函数、每环境 rollout 长度、学习率、折扣、GAE、PPO 裁剪、batch 划分、保存频率。

如果机器人膝关节方向写反，调 PPO 学习率通常救不了；如果 rollout 太短导致价值估计差，改 URDF 也不对症。把问题放回所属层，是调试效率的第一来源。

## 2.5 一次实验到底是什么

建议每次运行都生成独立目录：

```text
runs/g1_velocity/2026-09-01_14-30-12_seed42/
├── resolved_env.yaml
├── resolved_agent.yaml
├── git_state.txt
├── events.out.tfevents...
├── model_0100.pt
├── model_0200.pt
└── notes.md
```

“resolved” 指继承和默认值全部展开后的最终配置。只保存你手写的几行覆盖项，几个月后很可能无法恢复当时真正运行的参数。

## 2.6 最小复现实验

在投入长训练前，应能完成：

1. 同一 checkpoint 两次确定性 play 给出一致轨迹或足够接近的轨迹；
2. 固定一条观测，PyTorch 与 ONNX 输出在容差内一致；
3. 记录的观测维度、动作维度和策略网络声明一致；
4. 配置明确写出物理周期、decimation 和策略周期；
5. Git 工作区修改状态被记录，避免“代码改过但忘了提交”。
