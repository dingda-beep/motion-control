# 第 20 章：传统控制与学习控制如何选——按问题结构，不按阵营

> **所属部分**：第四部分 · 集成与实践。
>
> **前置知识**：[第 07 章](07-人形控制系统架构.md)、[第 19 章](19-Sim2Real与控制工程.md)，并至少了解传统和学习路线各一章。
>
> **核心问题**：怎样根据约束、数据、风险和可解释性选择或组合技术，而不是按流派站队？
>
> **下一步**：[第 21 章：项目路线](21-项目路线.md)。

## 怎么读这一章

- 第一遍先读第 0、1、2、4、7 节，先理解现代架构并存，再用任务约束、数据和失败后果做选择。
- 第 3 节的混合公式是组合范式示意，不是复制后就自动安全的完整控制器。
- 第 5～6 节用于把“演示效果好不好”改写成“失败概率、后果和恢复能力是否可接受”。

本章会同时使用前面两条路线的缩写，先快速复习：

- RL（Reinforcement Learning，强化学习）：通过环境交互和奖励学习控制策略；
- PD（Proportional-Derivative，比例—微分控制）：根据位置和速度误差纠偏；
- QP（Quadratic Programming，二次规划）：求解二次目标和线性约束；
- MPC（Model Predictive Control，模型预测控制）：在线预测未来并滚动重算；
- WBC（Whole-Body Control，全身控制）：协调全身任务并输出关节命令；
- EKF（Extended Kalman Filter，扩展卡尔曼滤波）：融合模型和传感器估计状态；
- VLA（Vision-Language-Action，视觉—语言—动作模型）：根据视觉和语言任务生成动作；
- IK（Inverse Kinematics，逆运动学）：根据希望手脚到达的位置反求关节姿态；
- CBF（Control Barrier Function，控制障碍函数）：把安全边界写成控制约束；
- OOD（Out of Distribution，分布外）：训练数据很少或没有覆盖的新情况。

我们不在抽象擂台上比较算法。本章始终用一个工厂任务来做选择：机器人要走到箱子旁，弯腰双手抓住箱子，再搬到货架。地面偶尔有小凸起，箱子重量不完全确定，工作区附近有人。每出现一个方法，都问它在这条任务链里解决哪一段、依赖什么信息、失败以后由谁接住。

## 0. 先回答一个常见误会：WBC、MPC 没有被统一“淘汰”

现代人形控制不是一条所有团队共同采用的单一路线。更准确地说，不同架构在重新分配三类工作：

```text
预测未来：接下来往哪里走、怎样接触
协调当前：这一刻手、脚、躯干和质心怎样同时满足任务
执行关节：电机怎样跟踪当前目标并处理真实反馈
```

- MPC 主要擅长在有限时间范围内预测未来并滚动重算；
- WBC 主要擅长把当前手、脚、质心、接触和关节限制协调成全身命令；
- RL 策略可以替代其中某一层，也可以学习从观测到全身关节目标的映射；
- 关节 PD、驱动器、安全限制和状态估计通常仍然存在。

所以变化的本质不是“旧模块按年份消失”，而是：**原来由显式模型和在线优化承担的某项决策，是否改由训练后的策略承担。** 即使算法模块被替换，预测未来、协调全身、处理约束和闭环执行这些物理问题也不会消失。

### 0.1 三种都算现代的架构

```text
模型控制：
规划/MPC → WBC → 关节力矩或目标

混合控制：
RL 给落脚点、身体目标或名义动作 → WBC/安全层 → 关节控制

全身学习：
全身目标与观测 → whole-body Actor → 全部关节目标 → PD/驱动器
```

它们不是严格的历史先后关系。选择哪一种，取决于模型可信度、任务变化、约束强度、数据、算力和失败后果。

### 0.2 不用 WBC 时，手臂怎样动

手臂控制从来不是只有一种入口。

轻载、上下肢耦合较弱时，可以分开处理：

```text
手的目标位置/姿态
→ 运动规划或逆运动学
→ 手臂关节目标
→ 关节 PD

下肢 RL 同时负责站立或行走
```

全身学习策略则可以把手臂也放进同一个动作向量：

```text
身体观测 + 手部/全身参考
→ 全身 Actor
→ 腿、腰、躯干、双臂的全部关节目标
```

这不是“手臂不再受控制”，而是手臂动作从显式 IK/WBC 的计算结果，变成统一策略输出的一部分。

当机器人探身抓取、快速挥臂、搬重箱或拉门时，手臂反作用会改变质心、角动量和脚底受力。此时简单的“下肢自己走、上肢自己动”容易失效，需要：

- WBC 显式协调手、躯干、质心和双脚；或者
- 一个在这些强耦合状态上训练过的全身策略；或者
- 学习策略提出目标，WBC 落实全身动力学与约束的混合方式。

真正的判断题不是“架构名字里还有没有 WBC”，而是：谁负责处理手臂动作对全身平衡造成的后果？如果没有任何模块承担，这个问题只是被遗漏，并没有被 RL 自动解决。

## 1. 两者把复杂度放在不同位置

传统控制：

```text
人工选择状态和模型
→ 显式写目标与约束
→ 部署时在线求解
```

学习控制：

```text
人工选择仿真、观测、动作、奖励和数据
→ 训练时大量采样优化
→ 部署时网络前向推理
```

两者都没有消灭建模。RL 的模型更多藏在仿真器、奖励和数据分布中。

两者也都必须闭环部署：传统控制器在线用 `f_model` 求解，学习策略在线用观测做网络推理；它们发出的都只是命令，最终由 `f_real` 和反馈决定实际运动。选择方法时应比较假设放在哪里、失败能否检测和恢复，而不是比较哪个 Demo 更像“智能”。

对工厂机器人来说，复杂地面行走可能难以精确手工建模，却有大量仿真试错机会；双手抓箱和关节限位又有明确几何与安全约束。任务本身已经暗示：最合适的答案很可能不是“全传统”或“全学习”，而是让不同模块承担自己更擅长、也更容易验证的责任。

## 2. 决策表

| 问题特征 | 更偏传统控制 | 更偏学习控制 |
|---|---|---|
| 动力学可较准确建立 | 是 | 不要求 |
| 严格约束很重要 | 强项 | 需安全层/约束 RL |
| 在线算力有限 | 可能困难 | 推理通常快 |
| 行为高度非线性、多接触 | 建模求解难 | 大规模训练有优势 |
| 需要解释失败原因 | 较容易 | 较困难 |
| 有大量仿真/动作数据 | 非必要 | 很有帮助 |
| 任务频繁改变约束 | 可在线重构 | 需条件化或重训 |
| 真实试错昂贵 | 可依赖模型 | 必须依赖仿真/离线数据 |

## 3. 典型组合

### RL 高层 + PD 低层

策略输出关节位置目标，PD 转成力矩。最普遍、简单。

### RL + 安全滤波 QP

策略给名义动作，QP 投影到满足力矩、接触或 CBF 约束的最近动作：

先用一个关节例子理解“投影”：

```text
RL 希望这一周期输出 5
安全规则只允许 [-3,3]
→ 安全滤波器在合法范围里选择离 5 最近的 3
```

多关节时，“合法范围”可能同时取决于关节限位、力矩、接触和当前状态，于是用 QP 在许多候选命令中寻找改动尽量小的合法命令。

```text
u^safe
=
arg min_u
‖u-u^RL‖²

同时满足
g_safe(x_hat,u)≤0
```

- `u^RL`：学习策略提出的名义命令；
- `u`：安全滤波器允许调整的候选命令；
- `‖u-u^RL‖²`：候选命令偏离策略原提议的平方距离；
- “同时满足”：英文资料常写作 `subject to` 或 `s.t.`，表示下面不是另一个目标，而是候选命令必须满足的条件；
- `g_safe(x_hat,u)≤0`：根据当前状态估计 `x_hat` 写出的安全约束集合；
- `arg min_u`：返回满足约束且离原命令最近的那个 `u`；
- `u^safe`：滤波器最终准备下发的安全命令。

CBF 是 Control Barrier Function，控制障碍函数。即使数学问题可行，`u^safe` 仍只是命令；若状态估计、模型或执行器有误，它不能自动保证真实世界绝对安全。

所以“安全滤波”的本质不是给 RL 输出贴一个安全标签，而是：**在动作下发前，再用显式边界检查并修改它。** 能保证到什么程度，取决于边界是否写对、状态是否估准、模型是否适用以及执行器是否真的跟得上。

还要避免另一个误会：`u^safe` 离 `u^RL` 越远，不代表越安全。滤波后的命令会真实改变机器人，并成为下一周期观测的原因；若滤波器持续削掉策略维持支撑所需的动作，反而可能制造跌倒。上线前应在同一模型、初始状态和扰动上，对“无滤波、旧滤波、新滤波”做 A/B，并记录修正幅度、触发比例以及哪些原本成功的场景变成失败。安全滤波器也需要闭环验收，不能只验证每个输出数字没有越界。

### MPC + 学习残差

```text
u
=
u_MPC
+Δu_learned
```

MPC 提供结构和约束，学习器补偿未建模动力学。

- `u_MPC`：模型控制器给出的名义输入；
- `Δu_learned`：学习器给出的输入修正量；
- 两者必须有相同单位和维度，并在相加后重新检查执行器和安全约束。

### 学习模型 + MPC

学习状态转移或模型残差：

```text
f_hat(x,u)
=
f_physics(x,u)
+f_θ^residual(x,u)
```

再放入 MPC 预测。

- `f_physics(x,u)`：显式物理模型预测；
- `f_θ^residual(x,u)`：参数为 `θ` 的学习模型所预测的模型残差；
- `f_hat(x,u)`：两者相加得到的修正模型；帽子表示估计模型，不是真实世界 `f_real`。

### RL 规划 + WBC

策略输出落脚点、质心参考或接触力，WBC 处理全身动力学和硬件约束。

### 模仿策略 + 传统状态估计

策略负责复杂动作，EKF 仍提供稳健基座状态。神经网络不必重写每一个成熟模块。

## 4. 失败模式对照

### 传统控制失败

- 模型假设不适用；
- 状态估计错误；
- 优化不可行；
- 权重尺度不对；
- 接触计划错误；
- 求解超时。

### RL 失败

- 奖励漏洞；
- 训练覆盖不足；
- 观测不可部署；
- 仿真/现实分布差异；
- 动作接口不一致；
- OOD 下无安全保证；
- 数据质量或采样失衡。

共同失败：

- 坐标系、单位、关节顺序；
- 延迟；
- 执行器饱和；
- 接触估计；
- 本体能力不足；
- 日志不完整。

## 5. 用风险而不是 Demo 选方案

评估：

```text
Expected Risk
=
Σ_i
P(failure_i)
×
C(failure_i)
```

- `P`：失败发生概率；
- `C`：失败代价。

- `i`：一种具体失败模式；
- `Σ_i`：对所有列入分析的失败模式求和；
- 这里的 `P` 是 probability（概率），不是第 05 章状态估计协方差矩阵；
- `C(failure_i)` 可以是维修成本、停机时间或人身风险等后果尺度，只有使用一致尺度时才能相加比较。

这个式子不是说罕见但灾难性的故障可以只靠一个平均数忽略。对人身安全等不可接受后果，还需要硬性停止条件和最坏情况分析。

仓库演示中的平均奖励或成功视频，只覆盖性能；工业部署还需考虑最坏情况、诊断、可恢复性和维护成本。

## 6. 回到贯穿全章的任务：工厂搬箱

要求：走到箱子旁、弯腰、双手抓取、搬运。

可能架构：

- 导航：视觉/地图规划路径；
- locomotion RL：复杂地面鲁棒移动；
- 抓取和末端轨迹：VLA 或运动规划；
- 全身 WBC：协调重心、手和接触；
- EKF/视觉定位：状态估计；
- 安全 QP/限幅：保护；
- 状态机：阶段切换与异常恢复。

上下肢完全分离在轻箱时可能够用；箱子变重时，手部外力显著影响平衡，应转向全身协调。

把它按时间顺序走一遍：

```text
1. 视觉和地图发现箱子与可行路径
2. 导航模块给出接近位置
3. locomotion RL 根据地形和速度命令行走
4. 传统状态估计持续提供身体当前判断
5. 到达箱子前，状态机要求减速并进入双脚稳定支撑
6. 运动规划或条件策略生成双手与躯干参考
7. WBC 协调手、质心、双脚接触和关节限制
8. 抓起箱子后，估计器和控制器从真实响应发现负载影响
9. 安全限幅或 QP 阻止明显越界命令
10. 任一关键条件不满足，状态机停止、放回或退出
```

这里没有一个模块“负责智能的一切”。方法选择真正决定的是责任边界：谁提出意图，谁落实物理约束，谁估计当前状态，谁监测失败，谁在异常时停止。

## 7. 选择流程

1. 明确控制输出和物理约束；
2. 判断可否获得足够准确的模型；
3. 判断是否有足够仿真、数据和算力；
4. 明确真机不可试错的边界；
5. 先实现最小可验证 baseline；
6. 用失败日志识别瓶颈；
7. 只在明确瓶颈处引入更复杂算法。

Baseline 不是最终方案，但它提供可比较的证据。

## 本章小结

- 传统控制把复杂度放在模型、约束和在线求解中，学习控制把复杂度放在数据、奖励、训练分布和网络中。
- 方案选择应从任务结构、可用模型、数据成本、实时性和失败后果出发，而不是从算法阵营出发。
- 工程系统常把预测、学习、全身控制、状态估计和安全滤波组合起来，每一层都要有明确输入输出与责任边界。

## 8. 练习

1. 需要严格保证关节力矩不超限时，哪种范式更容易直接表达？
2. 为什么“RL + PD”也算混合方法？
3. MPC 残差学习的风险是什么？
4. 何时上下肢分离最可能失效？

答案：1）显式约束优化；2）策略和传统反馈环共同组成控制器；3）残差可能破坏原控制器约束和稳定性，需要限幅/安全投影；4）上肢质量、负载或动作显著改变质心和角动量时。
