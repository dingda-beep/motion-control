# 第 21 章：从零到站立行走——给软件工程师的项目路线

> **所属部分**：第四部分 · 集成与实践的收束章。
>
> **前置知识**：[第 00～07 章](00-先看全局.md)、[第 20 章](20-传统控制与学习控制如何选.md)，以及与你选择路线对应的专题章。
>
> **核心问题**：怎样把概念拆成可实现、可测试、可回放、可安全部署的阶段？
>
> **完成标准**：每个阶段都有输入输出、指标、失败证据和停止条件，而不只是一个演示视频。

这不是“读完所有理论再写代码”的路线。每一阶段都有可见产物、验收指标和失败定位。

本章也不要求第一次把传统路线、RL 路线和模仿路线全部实现。先完成阶段 1～5 的共同地基，然后二选一：传统路线继续做阶段 6→7A，学习路线可以直接进入 7B；阶段 10 是独立扩展。**训练 RL 行走并不要求先实现一套 QP-WBC。** 每到一个阶段，只回查它引用的基础章，不要把整章当成一次性待办清单。

整条路线始终是同一个项目逐渐长大，不是十个互不相关的练习：

```text
阶段 1～3：先让软件中的“机器人”在坐标、骨架和模型上说得通
→ 阶段 4：让一个简单系统根据反馈稳定下来
→ 阶段 5：让完整人形的模型、接触、PD 和日志第一次说得通
→ 传统分支：阶段 6 用 WBC 协调全身约束，阶段 7A 扩展成行走
→ 学习分支：阶段 7B 直接在共同仿真地基上从零训练行走策略
→ 阶段 8～9：证明训练接口能够安全进入真实硬件
→ 阶段 10：在稳定运动基础上扩展到人的动作与风格
```

每一阶段都只比上一阶段多承担一种主要困难。这样失败时，才知道新引入的自由度、接触、算法或硬件接口是否是原因。

## 贯穿所有阶段的实验闭环

每完成一个功能，都按同一条证据链工作：

```text
提出假设
→ 写出可复现实现
→ 记录测量与中间量
→ 比较预测和实际
→ 尝试证伪假设
→ 保留或修正模型、代码与参数
```

例如“站不住是 PD（Proportional-Derivative，比例—微分）增益太小”只是一个假设。先记录期望/实际关节状态、力矩饱和、接触力、姿态估计和时间戳；若关节方向写反或脚已经打滑，数据会直接推翻这个假设。

失败时优先归到以下一类，再决定改哪里：

1. 目标或参考不合理；
2. 传感器、坐标、时间戳或状态估计错误；
3. 模型或接触模式与现实不符；
4. 运动学、动力学、摩擦或执行器约束不可行；
5. 求解器、策略或软件接口错误；
6. 驱动器没有实现命令或已经饱和；
7. 反馈频率、延迟或恢复逻辑不足。

“偶尔走通一次”只能证明存在一次成功样本。阶段完成应同时有重复实验、失败分布、中间日志和明确的安全退出条件。

- Linux；

- 部分仿真与强化学习平台以 Python 为主要入口，使用它们时只需把 Python 当作工具调用层；

- Git + 可复现实验配置；

## 阶段 1：数学和坐标代码化

### 任务

1. 用 Go 实现二维旋转和平移；
2. 写单元测试验证变换与逆变换；
3. 实现有限差分速度；
4. 对不同 `Δt` 比较欧拉积分误差。

### 验收

```go
// inverseTransform 与 transform 相乘后，应得到单位矩阵。
// testHandle 是测试框架句柄，不是变换矩阵。
requireMatrixClose(
	testHandle,
	Mul(inverseTransform, transform),
	identityTransform,
	1e-9,
)

// 合法旋转矩阵应满足 RᵀR=I，且行列式等于 1。
requireMatrixClose(
	testHandle,
	Mul(Transpose(rotation), rotation),
	identityRotation,
	1e-9,
)
if math.Abs(Det(rotation)-1.0) >= 1e-9 {
	testHandle.Fatal("旋转矩阵的行列式不等于 1")
}
```

测试句柄和变换矩阵不能同时简称为 `t`，否则一行代码里无法判断它指时间、测试对象还是变换。这里把测试对象、刚体变换、旋转矩阵和两种单位矩阵分别命名；正式实现还要根据矩阵尺寸定义对应类型。

### 你会学到

坐标系、单位和离散时间不是理论细节，而是接口契约。

## 阶段 2：二连杆 FK、IK、Jacobian

FK（Forward Kinematics，正运动学）由关节角计算末端位置；IK（Inverse Kinematics，逆运动学）由目标末端位置反求关节角；Jacobian（雅可比矩阵）描述关节速度怎样影响末端速度。

### 任务

1. 手写二连杆 FK；
2. 用有限差分验证解析 Jacobian；
3. 用阻尼伪逆做 IK；
4. 可视化奇异位形附近关节速度。

有限差分验证：

```text
J_(:,i)
≈
(p(q+εe_i)
-p(q))/(ε)
```

- `e_i`：只有第 `i` 项为 1 的基向量；
- `ε`：很小的角度扰动。
- `q`：当前关节角向量；
- `p(q)`：正运动学算出的末端位置；
- `J_(:,i)`：雅可比的第 `i` 列；冒号表示保留这一列的所有行；
- 整条式子在问：只把第 `i` 个关节增加一点 `ε`，末端位置变化量除以这点关节变化，是否接近解析雅可比第 `i` 列。

### 验收

- FK 与手算示例一致；
- Jacobian 相对误差小；
- 可达点 IK 收敛；
- 不可达点不会产生 NaN（Not a Number，非法数值）；
- 关节限位有效。

## 阶段 3：读懂一个 URDF

URDF 是 Unified Robot Description Format，统一机器人描述格式，用来记录机器人的连杆、关节、质量和碰撞几何。

### 任务

1. 找一个开源人形 URDF；
2. 列出 link、joint、parent、child；
3. 检查关节轴、限位、质量、惯量；
4. 用 Pinocchio 加载并打印 `nq`、`nv`；
5. 计算左右脚和双手的 FK/Jacobian。

### 验收

- 解释为什么浮动基 `nq != nv`；
- 给定默认姿态时脚底高度合理；
- 左右关节方向和命名明确；
- 总质量等于所有 link 质量和。

## 阶段 4：单关节与倒立摆控制

本阶段使用：

- PD（Proportional-Derivative，比例—微分控制）：根据位置和速度误差纠偏；
- LQR（Linear Quadratic Regulator，线性二次调节器）：为线性系统系统化地求反馈增益。

### 任务

1. 仿真单关节 PD；
2. 扫描 `K_p,K_d`，画阶跃响应；
3. 加饱和、噪声和延迟；
4. 实现小车倒立摆 LQR；
5. 比较开环、PD、LQR。

### 指标

- rise time：上升时间；
- overshoot：超调；
- settling time：稳定时间；
- steady-state error：稳态误差；
- 最大控制输入。

## 阶段 5：MuJoCo 人形落地与接口冒烟测试

这一阶段的共同目标不是规定“必须用哪种高级控制器”，而是确认完整人形的模型、关节接口、接触、PD、频率和日志能够说同一种语言。传统路线可以在这里使用姿态保持、重力补偿或最简 WBC（Whole-Body Control，全身控制）尝试闭环站立；学习路线不必先造一个 WBC，它会在 7B 的第一步让随机策略从摔倒中学会站立。

### 任务

1. 导入 URDF 或 MJCF（MuJoCo XML Model Format，MuJoCo XML 模型格式）；
2. 先用固定基检查关节 PD；
3. 切换浮动基；
4. 生成静态站立姿态并检查双脚碰撞；
5. 无控制释放一次，确认倒下方向、接触与日志符合物理直觉；
6. 若当前路线已有站立控制器，再做闭环承重和小扰动。

### 验收

- 固定基关节目标与反馈的索引、方向、单位一致；
- 浮动基和双脚接触没有 NaN（Not a Number，非法数值）、爆炸或明显穿透；
- 日志可对齐状态、参考、命令和接触力。

若本阶段已经加入站立控制器，再要求站立 `30 s` 不摔、力矩不长期饱和、两脚法向力和约为 `mg`、支撑脚滑移在阈值内。走 7B 的项目把这四项作为“从零 PPO 站立”通过后的第一道能力门槛，而不是 WBC 前置作业。

失败时先检查：

1. 关节方向与零位；
2. 碰撞体和地面；
3. PD 与控制频率；
4. 初始姿态；
5. 质量和单位；
6. 才检查高级控制。

## 阶段 6：QP-WBC（传统路线分支）

QP-WBC 表示“用二次规划实现的全身控制器”：QP 负责统一求解任务和约束，WBC 负责把全身目标落实成关节命令。

选择 RL 路线时可以暂不实现本阶段，直接进入 7B。跳过的是“自己写在线 QP-WBC”这个项目任务，不是跳过关节 PD、接触、动力学含义、硬件限制和反馈闭环。

### 任务

1. 决策变量先只用 `v_dot,τ,λ`；
2. 加全身动力学等式；
3. 加双脚接触加速度约束；
4. 加摩擦与力矩限幅；
5. 先跟踪质心高度；
6. 再加躯干和摆动脚任务。

这里 `v_dot` 是全身广义加速度，`τ` 是关节电机力矩，`λ` 是环境施加给机器人的接触力或 wrench。三者都是 QP 当前要找的候选量，真正下发给硬件的通常只有关节命令。

### 单元测试

- 静态站立解满足力平衡；
- 任务清零时不产生异常大力矩；
- 人工给冲突约束时能检测 infeasible；
- QP 每周期耗时分位数满足 deadline；
- 所有等式残差在容差内。

- `infeasible`：约束彼此冲突，不存在同时满足它们的解；
- `deadline`：本控制周期允许的最晚完成时间；即使平均耗时很低，频繁超过 deadline 仍会引入控制延迟；
- 残差：把求解结果代回等式后，左、右两边还差多少。

### 行为验收

站立 → 小幅蹲起 → 重心左右移动 → 单脚减载 → 原地踏步。

不要直接从站立跳到行走。

## 阶段 7A：传统控制行走

SRBD（Single Rigid Body Dynamics，单刚体动力学）把全身近似成一个刚体；Convex MPC（Convex Model Predictive Control，凸模型预测控制）用这个简化模型快速预测未来接触力。

### 最小路线

1. 固定时间步态状态机；
2. Raibert/Capture Point 落脚点；
3. 摆动脚三次或五次多项式轨迹；
4. SRBD Convex MPC 求接触力；
5. WBC 求关节力矩。

### 验收

- 速度命令阶跃响应；
- 左右步态对称性；
- 摩擦锥余量；
- 接触切换力矩连续性；
- 推扰后的捕获步；
- 求解器最坏耗时。

## 阶段 7B：RL 行走

### 最小路线

1. Isaac Lab 中从随机权重训练固定参数平地站立；
2. 加水平速度命令，先确认前进与回零；
3. 显式采样站立、移动、移动→停止→重新起步；
4. 再扩展横移、后退、快速转弯与更宽速度；
5. 加随机初始姿态和推扰；
6. 加 domain randomization（域随机化）；
7. 需要时再加地形 curriculum（课程学习）；
8. 用独立场景套件筛选 checkpoint；
9. 导出 ONNX（Open Neural Network Exchange，开放神经网络交换格式）或 TorchScript，逐输入比较训练端和部署端推理结果。

“从零训练”是从随机网络参数开始，不表示不再由人定义任务。机器人模型、观测、动作接口、奖励、命令分布、终止、课程和评估器仍然决定它练习的世界。一次成功训练可能消耗数亿仿真步；这说明并行采样量很大，不代表每个项目版本都重新从零、也不代表最后一个 checkpoint 最好。

统一速度策略还要单独设计样本占比：

```text
稳定零命令
+ 持续移动
+ 移动中切到零
+ 停稳后重新起步
+ 方向和速度切换
```

若零命令太少，停车学不会；若零命令和站立奖励过多，“永远不走”可能成为便宜答案。命令范围写进配置还不够，要确认 rollout 中各类状态和过渡实际出现了多少。

### 训练配置必须版本化

```text
robot model hash
physics dt
policy dt / decimation
observation order and scale
action scale
reward weights
randomization ranges
terrain seed
network architecture
checkpoint and code commit
```

这张清单是在冻结“训练问题到底是什么”：模型文件哈希标识机器人版本，`physics dt` 是物理仿真时间步，`policy dt` 是策略更新间隔，`decimation` 是两者的步数比；观测顺序、动作尺度、奖励权重和随机范围共同决定策略学到的接口。只保存神经网络 checkpoint 而不保存这些配置，通常无法可靠复现实验。

还应记录每次续训的父 checkpoint、改了哪些题目以及新增多少采样。版本谱系表示：

```text
继承上一版参数
→ 用当前策略重新采集 rollout
→ 在修改后的训练题目上继续更新
```

它不是把所有旧数据永久放在一个大数据集中，也不是每个版本都做相同步数的全量重训。

### 验收

- 不只看训练平均奖励；
- 在未见 seed、质量、摩擦、延迟上报告成功率；
- 记录最坏分位；
- 关闭随机化重新评估名义性能；
- 观测中无仿真特权泄漏；
- 分别报告站、走、停、重启、横移、转弯和扰动场景；
- 用相同 seed 与初始快照比较基线和候选的 rescue/harm；
- 训练末尾 checkpoint 不自动获得发布资格。

这里 `seed` 是随机种子，用来复现同一批初始状态和扰动；`rescue` 表示基线失败而候选成功，`harm` 表示基线成功而候选反而失败。只看两者各自的总成功率，可能看不见新增能力正在伤害哪些旧场景。

若需要定位瓶颈，可以引入第 15 章的 Oracle 诊断：给参照策略或 gate 临时提供仿真真值。Oracle 也失败，更应检查任务、动作、奖励和探索；Oracle 成功而部署观测策略失败，更应检查可观测性、估计和历史。Oracle 只用于归因，不得悄悄进入最终真机输入。

## 阶段 8：真机前接口审计

建立一个逐元素表：

| 索引 | 训练观测 | 单位 | 坐标系 | 真机来源 | 范围 |
|---:|---|---|---|---|---|
| 0..2 | command velocity | m/s, rad/s | body | joystick | ... |
| ... | ... | ... | ... | ... | ... |

动作也做相同表格。

这一阶段的产物不是“某个模型文件”，而是一份不可拆散的发布候选：

```text
policy.onnx
+ deploy contract
+ 状态机与有状态事件参数
+ 硬件和安全 profile
+ 文件哈希与 manifest
+ 仿真/回放验证报告
```

- profile：某种硬件或某一级真机实验专用的一组参数，例如吊架测试的速度和安全上限；
- manifest：发布清单，记录这一版绑定了哪些文件、各自哈希和验证证据。

deploy contract（部署契约）至少绑定：

- 观测字段、顺序、历史长度、单位、坐标系和归一化；
- 关节顺序、默认姿态、动作缩放与 PD 增益；
- 策略频率、发送频率、保持或插值方式；
- 安全阈值、命令包络和适用硬件；
- 事件触发、持续时间、复位/重置与最大控制权限。

用脚本自动比较训练配置、部署配置和模型的输入输出 shape（张量每个方向有多少个数字）、顺序、数值数组与哈希。检查通过只证明接口静态一致，不证明真机一定稳定，但能提前挡住大量“维度一样、语义不同”的错误。

### 离线回放

用真机静止日志喂给策略，检查：

- 输出是否接近安全站立；
- 是否有 NaN/Inf（非法数值/无穷大）；
- 是否频繁饱和；
- 轻微传感噪声是否导致巨大动作变化。

还要做部署侧安全 A/B：对同一组仿真状态或日志，分别运行原始策略目标与保护后目标，统计每个关节的修正比例、最大修正量和场景成败。若保护后原本成功的行走普遍失败，不能因为每个数字都更小就批准上机。

## 阶段 9：真机渐进部署

1. 电机断使能，验证通信与观测；
2. 单关节低力矩；
3. 悬空全关节；
4. 吊架下站立；
5. 重心小范围移动；
6. 原地踏步；
7. 低速直行；
8. 转弯；
9. 扰动；
10. 复杂地形。

在第 1 步之前先验收控制权：

```text
确认操纵杆回中和初始姿态安全
→ 请求原控制服务释放/切换
→ 等待硬件 ACK
→ 确认命令通道只有预期发布者
→ 发送零运动保持
→ 才允许进入策略状态
```

退出路径同样要验收：人工急停、通信超时、主进程异常和最长运行时间到达后，都能进入阻尼并恢复原生安全模式。主进程崩溃后无法执行自己的 `finally`，因此恢复还需要独立系统服务或硬件看门狗。

若策略是 `50 Hz`、底层命令通道是 `500 Hz`，明确记录采用零阶保持还是插值，并验证发送线程停止、策略超时和新命令替换的行为。对耗时至少记录 P50（中位数）、P99（99% 的周期不超过的值）、max（观察到的最大值）和连续 deadline miss；必须注明计时器包住的是纯网络推理，还是传感器更新、观测、日志、推理与发布整段。

每一步定义：

- 最大试验时长；
- 成功标准；
- 自动停止条件；
- 人工急停角色；
- 回放日志检查表。

发布二进制、模型和配置时采用可恢复流程：先写临时文件，校验非空、目标架构和哈希，完成同步后再原子重命名。这里“原子重命名”可以先理解成：最终文件名要么仍指向完整旧文件，要么一次切到完整新文件，不暴露复制到一半的中间状态。不要让断电或重启把正在使用的控制程序留成半个文件。

## 阶段 10：模仿学习

这一阶段会用到：

- RSI（Reference State Initialization，参考状态初始化）：从参考动作的随机时刻开始训练；
- AMP（Adversarial Motion Priors，对抗运动先验）：用判别器学习动作风格；
- PPO（Proximal Policy Optimization，近端策略优化）：用于更新控制策略。

1. 选一段 3–5 秒、低动态、高质量动作；
2. 统一坐标和频率；
3. 做受限 retarget；
4. 检查位置、速度、接触连续；
5. 用 RSI + adaptive sampling 训练 DeepMimic；
6. 再尝试多动作或 AMP。

先学会单动作的完整数据管线，再扩大到 AMASS（Archive of Motion Capture as Surface Shapes，大规模人体动作捕捉集合）或 LAFAN1（Ubisoft La Forge 发布、常用于动作预测与补间的人体动作数据集）规模。

## 贯穿案例：G1-Command-RL 怎样从零训练到吊架真机

[G1-Command-RL](https://github.com/dingda-beep/G1-Command-RL) 是本章路线的一份真实补充：它从随机权重开始训练 Unitree G1 的统一速度命令策略，没有先实现 QP-WBC，再逐步完成仿真评估、专家诊断与组合、部署契约、吊架真机和原始低层命令链测试。

### 训练出来的不是“每个速度一张模型”

同一个条件策略读取前进、横移和转向命令，每 `20 ms` 输出 29 个关节目标；底层 PD 负责把目标变成关节作用。站立、行走、停止和重新起步是许多周期组成的行为，不是 4 张按按钮切换的模型。

### 最难的不是让平均奖励上涨

训练过程中出现过：零命令样本太少导致停车长尾、静态能力被后续训练遗忘、恢复专家救回异常场景却伤害日常基线、Student 离线动作误差很小但闭环接触轨迹分开。项目使用固定场景、独立评估、相同 seed/快照的 harm/rescue 统计与多版本谱系，而不是只看最后 checkpoint。

### Oracle 和专家先用于定位，不急着宣布最终架构

额外真值、专项恢复专家和组合教师先回答“能力是否存在、信息是否足够、瓶颈在训练还是观测”。最终部署没有读取仿真接触真值，而是使用可部署的 IMU 线加速度、10 帧历史和一维因果事件记忆。

### 真机成功依赖闭环外围与网络一起正确

早期真机失败最终定位到部署限幅过严；一次所谓推理超时定位到同步日志 I/O；原始 `rt/lowcmd` 测试还需要单一发布者检查、`50 Hz→500 Hz` 命令保持、独立超时恢复和原子文件发布。这些都不是 PPO 的超参数，却直接决定策略能否成为真实控制器。

因此这个项目最值得复用的路线不是某组奖励权重，而是以下证据顺序：

```text
先证明任务可学
→ 再证明观测和动作契约可部署
→ 再用独立场景筛选 checkpoint
→ 再证明安全后处理没有破坏能力
→ 再证明控制权、时序和恢复路径可靠
→ 最后才逐级扩大真机命令包络
```

当前案例证明的是吊架条件下的真机控制验收，不应自动外推成无保护绳、任意地形或量产安全结论。证据边界写清楚，本身就是项目成熟度的一部分。

## 路线小结

- 每个阶段都先验证最小因果链，再增加自由度、接触、预测、学习或真机风险；不要从静态站立直接跳到复杂行走。
- 验收必须包含重复实验、失败分布、中间日志和安全停止条件，不能只以一次成功视频作为证据。
- 传统分支可以通过 QP-WBC 进入行走，学习分支也可以在共同仿真地基上直接从零训练；两条路都必须承担接触、执行器和反馈的现实后果。
- 数学、仿真、控制、学习和部署最终应汇合到同一套可版本化接口、发布清单与可回放实验中。

## 最终作品

建议仓库至少包含：

```text
docs/
configs/
models/
release/
src/control/
src/estimation/
src/simulation/
src/deployment/
tests/
logs/schema.md
experiments/
```

其中 `release/` 不应只放一份权重；它应保存本次获准测试的模型、部署契约、安全 profile、manifest、哈希和验证报告。

最终报告应对比至少一个传统 baseline 和一个 RL baseline，不只展示视频。
