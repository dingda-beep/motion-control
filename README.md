# 机器人运动与控制：给软件工程师的入门教程

这套教程写给这样的读者：有 Go 软件开发经验，理解模块边界和状态机，但高等数学已经生疏，也没有系统学过机器人学。

它不是原始《人形机器人运动控制 Know-How》的拆分版，而是一次面向初学者的重构。原文的算法脉络被保留，同时增加了数学地基、软件类比、数值例子、符号表、误区和循序渐进的实践项目。

## 怎么读

建议严格按顺序读第 00～07 章。它们解决后文反复依赖的坐标、速度、力、反馈和优化概念。读完后有两条路线：

- 传统控制路线：08 → 09 → 10 → 11 → 12 → 13 → 14
- 学习控制路线：15 → 16 → 17 → 18 → 19 → 20

最后阅读 21～23 章，把两条路线放回同一个工程系统。

可以把全书分成四个难度阶段，不必第一次就吃透所有公式：

| 阶段 | 章节 | 第一次阅读的目标 |
|---|---|---|
| 建立地基 | 00～07 | 能说清状态、坐标、运动学、动力学、反馈和优化分别解决什么问题 |
| 看懂经典行走 | 08～14 | 能沿着“高层规划接触力/轨迹，低层落实关节命令，估计器提供反馈”追踪数据流 |
| 看懂学习控制 | 15～20 | 能区分训练与部署、状态与观测、奖励与现实目标、参考动作与真实执行 |
| 动手与选型 | 21～23 | 能选择一条项目路线，并用日志和验收指标定位问题 |

第 00～05 章是最低前置。如果这里仍分不清位置与速度、运动学与动力学、参考与测量，不建议靠背缩写继续读 WBC 或 PPO；先完成章末练习和第 22 章前四个小项目会更省时间。

遇到公式时不要试图背诵。先读公式后的“每个符号是什么意思”，再看数值例子，最后把公式翻译成代码。为了兼容不支持 LaTeX 的普通 Markdown 预览器，本教程采用接近代码的纯文本记法：

- 变量放在反引号或 `text` 代码块中，向量、矩阵、标量由紧邻公式的符号解释和 shape 明确；
- 大写字母（如 `R`、`M`）通常表示矩阵，小写字母（如 `m`）通常表示标量或向量；
- `_` 表示下标，如 `x_k` 是第 `k` 个离散时刻的状态；
- `^` 表示上标，`ᵀ` 表示转置，`⁻¹` 表示逆；
- `_dot` 表示一阶时间导数，`_ddot` 表示二阶时间导数，如 `p_dot` 是速度、`p_ddot` 是加速度；
- `·` 表示乘法，`‖x‖` 表示向量 `x` 的长度。

文档中的程序示例统一使用 Go，并尽量给关键步骤添加中文注释。示例重点是表达数据流和算法结构，其中 `Matrix`、`Vector`、`MatVecMul` 等名称代表线性代数类型或辅助函数，不绑定某个具体 Go 数值库。

缩写第一次出现时采用：

```text
MPC（Model Predictive Control，模型预测控制）
```

英文全称用于查论文和代码，中文含义用于理解；正文还会说明它在当前系统中负责什么。无需先背缩写，可随时查阅第 23 章。

### 初学者遇到看不懂的地方怎么办

这套教程不要求你靠猜测跨过术语。如果一段话读完后，你只能复述名词，却说不出一个具体场景，说明铺垫还不够。建议按下面的顺序处理：

1. 先找这一节开头的实际问题：机器人此刻想做什么？
2. 再找一个能代入数字的最小例子；不要一上来研究完整人形。
3. 对照公式下方的符号解释，确认输入、输出、维度和单位。
4. 最后再记专业术语，并确认它描述的是现象、原因还是解决方法。

例如，不要把“奇异位形就是雅可比丢失秩”当成解释。对初学者更有用的学习顺序是：先观察二连杆伸直后不能继续向外移动，再算出此时任意关节速度都只能产生上下方向的瞬时速度，最后才把“可产生的独立方向变少”命名为“雅可比丢失秩”。

本教程中的软件类比只用于补充已经讲清楚的物理过程，不能代替物理例子。若类比和机器人场景只能理解一个，以机器人场景为准。

## 贯穿全书的心智模型

把机器人看成一个高频、强实时、状态不完全可观测的闭环系统：

```text
人的目标 → 任务与参考 → 控制器/策略 → 电机 → 真实机器人与环境
                         ↑                    │
                         └─ 估计状态 ← 传感器 ┘
```

![完整的人形机器人运动控制闭环](picture/full_motion_control_loop.svg)

控制器不是“算出一个漂亮动作”的函数，而是持续回答：

> 在我对当前状态的估计并不完美、模型也不完全准确的情况下，下一毫秒给每个电机什么命令，才能让机器人逐步接近期望，同时不违反物理约束？

全书反复使用下面五个问题：

1. 真实世界现在处于什么状态 `x_real`？
2. 传感器实际提供了什么测量 `y`？
3. 控制器根据证据形成了什么估计 `x_hat`？
4. 模型 `f_model` 预测候选输入 `u` 会带来什么后果？
5. 真实世界 `f_real` 最终发生了什么，反馈又怎样改变下一次决定？

`x_real` 通常无法直接获得；`x_hat` 是估计器的当前信念；模型预测也不是现实承诺。区分这三者，是阅读后续所有算法的基础。
