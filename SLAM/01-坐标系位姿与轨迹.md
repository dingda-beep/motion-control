# 01 坐标系、位姿与轨迹：数字不动，换一把尺子，坐标就变了

> 前置：只需要读过[00 先看全局](00-先看全局.md)。
>
> 本章目标：真正理解坐标系、点、位姿和坐标变换分别是什么，以及 `T_ab` 到底把谁变到谁。

## 1. 同一个杯子为什么可以有许多组坐标

桌上有一个杯子。你站在桌子南边说：

```text
杯子在我前方 1 米、右边 0.3 米。
```

另一个人站在桌子东边，他可能说：

```text
杯子在我左边 1 米、前方 0.3 米。
```

杯子没有移动，数字却不同。因为坐标不是物体自身携带的绝对标签，而是：

> 选定一个原点和一组方向后，对物体位置作出的描述。

这套“原点 + 坐标轴方向”就是坐标系（Frame）。

任何坐标都必须能补完整这句话：

```text
某个点，在某个坐标系中，坐标是多少。
```

不说坐标系，只说“点是 `(1, 2, 3)`”，信息是不完整的。

## 2. SLAM 中常见的四种坐标系

### 2.1 世界坐标系 `w`

World frame，记作 `w`。它给整条轨迹和整张地图一个统一参考。

没有 GPS 时，它通常是人为选的，例如把第一帧相机位置设为原点。世界坐标系不是宇宙真理，只是大家约好使用的公共尺子。

### 2.2 机体坐标系 `b`

Body frame，记作 `b`，固定在机器人机身上。机器人移动时，它跟着移动。

例如约定：

- `x` 轴朝机器人前方；
- `y` 轴朝左；
- `z` 轴朝上。

### 2.3 相机坐标系 `c`

Camera frame，记作 `c`，固定在相机上。计算机视觉常约定 `z` 轴朝镜头前方，但不同软件约定可能不同，必须查清楚。

### 2.4 IMU 或激光坐标系 `i、l`

IMU frame 记作 `i`，LiDAR frame 记作 `l`。它们固定在各自传感器上。

相机和 IMU 都装在机器人上，但安装位置和方向通常不同。从一个传感器坐标系变换到另一个坐标系的固定关系叫**外参**。

## 3. 点、坐标和位姿不是一回事

以墙角点 `P` 为例：

- `P`：现实中的那个几何点；
- `p_w`：点 `P` 在世界坐标系中的坐标；
- `p_c`：同一点 `P` 在当前相机坐标系中的坐标；
- 相机位姿：相机坐标系相对于世界坐标系的位置与方向。

当相机移动时：

- 墙角 `P` 可以没动；
- `p_w` 可以不变；
- `p_c` 会变化；
- 相机位姿也会变化。

SLAM 的几何主线，就是用相机里不断变化的观测，推断相机位姿和地图点的世界坐标。

## 4. 二维世界里，坐标变换怎样发生

先不碰三维旋转。假设机器人坐标系 `b` 中有一个点：

```text
p_b = [1, 0]ᵀ
```

它表示这个点在机器人正前方 1 米。上标 `ᵀ` 表示把横着写的数字看作一列。

现在已知机器人在世界中的状态：

- 位于世界坐标 `(2, 1)`；
- 相对世界逆时针旋转 90°。

机器人前方在世界中就朝向世界 `y` 轴。因此点的世界坐标是：

```text
先旋转：[1, 0] → [0, 1]
再平移：[0, 1] + [2, 1] = [2, 2]
```

写成公式：

```text
p_w = R_wb p_b + t_wb
```

每个符号都解释：

- `p_b`：点在机体坐标系 `b` 中的坐标；
- `p_w`：同一点在世界坐标系 `w` 中的坐标；
- `R_wb`：把一个用 `b` 表达的方向旋转成用 `w` 表达；
- `t_wb`：机体原点在世界坐标系中的位置；
- 下标 `wb`：本教程统一理解为“从 `b` 变到 `w`”。

把整句话念出来：

> 用 `R_wb` 旋转机体系坐标，再加上机体原点在世界中的位置 `t_wb`，得到世界系坐标。

只要能把公式念成这句话，就不容易乘反。

## 5. 为什么既有旋转又有平移

坐标系变化可能包含两件事：

1. 两套坐标轴方向不同，所以要旋转；
2. 两套坐标系原点不同，所以要平移。

旋转改变一个向量的表达方向，平移改变坐标原点。顺序不能随便交换。

```text
p_w = R_wb p_b + t_wb
```

这里必须先旋转点在机体系中的局部坐标，再加机体原点的位置。

如果对一个纯方向向量，例如“机器人前进方向”，只需要旋转，不加平移。因为方向没有“位于哪个原点”的问题。

## 6. 齐次变换矩阵只是把两步装进一个盒子

为了反复组合旋转和平移，工程中常把它们写进一个矩阵：

```text
       [ R_wb  t_wb ]
T_wb = [  0      1  ]
```

三维情况下：

- `R_wb` 是 `3×3` 旋转矩阵；
- `t_wb` 是 `3×1` 平移向量；
- 最后一行是 `[0, 0, 0, 1]`；
- `T_wb` 整体是 `4×4`。

给三维点末尾补一个 `1`：

```text
p_b_h = [x_b, y_b, z_b, 1]ᵀ
```

下标 `h` 表示齐次坐标。于是旋转加平移可以统一写成：

```text
p_w_h = T_wb p_b_h
```

它没有创造新的物理，只是把“先旋转、再平移”装进一个便于连乘的盒子。

## 7. 变换为什么能连续相乘

假设：

- `T_bc`：把相机坐标变成机体坐标；
- `T_wb`：把机体坐标变成世界坐标。

一个相机坐标 `p_c` 先变到机体系，再变到世界系：

```text
p_b = T_bc p_c
p_w = T_wb p_b
```

代入：

```text
p_w = T_wb T_bc p_c
```

因此：

```text
T_wc = T_wb T_bc
```

读矩阵链时从右往左追踪：

```text
c --T_bc--> b --T_wb--> w
```

中间的 `b` 接上了，最后得到从 `c` 到 `w`。

这和单位换算很像：

```text
厘米 → 米 → 千米
```

不能把顺序反过来。

## 8. 逆变换是什么

`T_wb` 把机体系坐标变成世界系坐标。如果要反过来，就使用它的逆：

```text
T_bw = T_wb⁻¹
```

于是：

```text
p_b = T_bw p_w
```

二维生活例子中，已知点在世界坐标 `[2, 2]`，机器人在 `[2, 1]` 且朝世界正 `y` 方向：

1. 先减去机器人在世界中的平移，得到 `[0, 1]`；
2. 再按相反方向旋转 90°，得到机器人坐标 `[1, 0]`。

三维刚体变换的逆可以写成：

```text
        [ R_wbᵀ   -R_wbᵀ t_wb ]
T_bw  = [   0            1      ]
```

这里旋转矩阵的逆等于转置：`R⁻¹ = Rᵀ`。第一遍不需要背公式，只需明白逆变换在撤销原来的平移和旋转。

## 9. `T_wc` 还是 `T_cw`：为什么不同资料看起来相反

这是 SLAM 最常见的阅读障碍之一。不同作者的下标习惯确实可能相反。

本教程固定使用：

```text
T_ab：把 b 坐标系中的坐标，变成 a 坐标系中的坐标
p_a = T_ab p_b
```

因此：

- `T_wc`：相机到世界，描述相机在世界中的位姿；
- `T_cw`：世界到相机，常用于把世界地图点投影到当前相机；
- 两者互为逆：`T_cw = T_wc⁻¹`。

但读外部代码时不要只看变量名字。最可靠的判断是找到它实际参与的等式：

```text
p_left = T p_right
```

看清输入输出，才能知道 `T` 的真实方向。

## 10. 为什么投影时常用 `T_cw`

地图点通常保存在世界坐标 `p_w` 中。相机成像公式需要点在相机坐标系中的坐标 `p_c`。

因此先做：

```text
p_c = T_cw p_w
```

再把 `p_c = [X, Y, Z]ᵀ` 投影为像素。下一章后面的相机章节会推导投影公式。

这解释了一个常见现象：系统保存的“相机位姿”可能是 `T_wc`，但计算重投影时会用它的逆 `T_cw`。

## 11. 轨迹就是随时间变化的一串位姿

如果每个时间点都有一个位姿：

```text
T_wc(0), T_wc(1), T_wc(2), ...
```

它们合起来就是相机轨迹。括号中的数字表示时间或帧编号。

相邻位姿之间的相对运动可以写成：

```text
T_c0_c1 = T_c0_w T_w_c1
```

它表达“第 1 帧相机坐标怎样变到第 0 帧相机坐标”。具体软件可能使用相反方向，所以仍要回到输入输出等式检查。

里程计通常先估计相邻位姿变化，再逐步累乘成全局轨迹。每一步的小误差也会一起被累乘，这就是漂移的一条来源。

## 12. 旋转矩阵、欧拉角和四元数分别在干什么

它们都不是三种不同的旋转，而是同一个空间旋转的不同表达方式。

### 欧拉角

用绕几个轴的角度表示，直观，适合给人看。但旋转顺序不同结果不同，还可能遇到万向锁，不适合所有内部计算。

### 旋转矩阵

用 `3×3` 矩阵表示，变换点和组合旋转很直接，但 9 个数字实际只含 3 个自由度，优化时需要维持正交约束。

### 四元数

用 4 个数表示旋转，适合插值和数值计算，但必须保持单位长度，而且 `q` 与 `-q` 表示同一个旋转。

### `SO(3)` 与 `SE(3)`

- `SO(3)`：所有合法三维旋转组成的空间；
- `SE(3)`：所有合法三维刚体位姿，也就是旋转加平移组成的空间。

它们不是为了显得高深而造的名词，而是在提醒我们：旋转不是普通三维向量，不能永远直接相加。第 07 章讲优化时再解释为什么需要在当前位姿附近施加一个“小旋转增量”。

## 13. 位姿估计值与真实位姿要严格区分

SLAM 中常有：

```text
T_wc_real：现实中的真实相机位姿，真机通常未知
T_wc_hat ：算法估计的相机位姿
```

算法用 `T_wc_hat` 把地图点投到图像中，再和真实像素测量比较。两者不一致产生重投影残差，然后优化器修正 `T_wc_hat`。

不要把文档中简写的 `T_wc` 自动理解成真值。除非明确处于仿真真值或外部测量上下文，它通常是某个估计。

## 14. 一个数值例子：把相机点放进世界

为避免三维旋转遮住本质，仍用二维：

```text
相机在世界位置 t_wc = [3, 2]ᵀ
相机相对世界逆时针旋转 90°
某点在相机正前方 2 米：p_c = [2, 0]ᵀ
```

旋转矩阵：

```text
       [ 0  -1 ]
R_wc = [ 1   0 ]
```

计算：

```text
p_w = R_wc p_c + t_wc

    = [0, 2]ᵀ + [3, 2]ᵀ

    = [3, 4]ᵀ
```

含义是：相机自己的“前方”经过旋转后对应世界的上方，再加相机原点的世界位置。

## 15. 最常见的五种错误

1. **只写一个三维数字，不写属于哪个坐标系。**
2. **把 `T_wc` 和 `T_cw` 当成同一个矩阵。**
3. **矩阵链不从右向左检查坐标系是否接得上。**
4. **把点和方向都加上平移。**方向向量只旋转。
5. **把算法估计的位姿当成现实真值。**估计可能漂移，也可能被后端再次修改。

## 16. 本章最小结论

```text
点 P 是现实中的几何对象
p_c 是 P 在相机坐标系中的数字
p_w 是 P 在世界坐标系中的数字
T_wc 把相机系坐标变成世界系坐标
T_cw = T_wc⁻¹ 把世界系坐标变成相机系坐标
轨迹是一串随时间变化的位姿
```
