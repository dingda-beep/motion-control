# 05 两帧运动估计：先数清楚已知的是二维还是三维，再选择几何工具

> 前置：[数据关联](04-数据关联与特征匹配.md)。
>
> 本章目标：建立 2D–2D、3D–2D、3D–3D 的统一视角，理解它们的输入、输出、信息缺口和失败条件。

## 1. 所有名词先放进同一个问题

机器人拍了两帧图像，或获得两帧点云。我们想知道从第一时刻到第二时刻，传感器发生了怎样的刚体运动：

```text
旋转 R + 平移 t
```

方法不同，不是因为它们在解完全不同的世界，而是因为手中对应点的已知信息不同：

| 情况 | 第一侧 | 第二侧 | 常见工具 | 主要输出 |
|---|---|---|---|---|
| 2D–2D | 图像像素 | 图像像素 | 本质矩阵/基础矩阵 | 相对旋转、平移方向 |
| 3D–2D | 已知三维地图点 | 图像像素 | PnP | 当前相机位姿 |
| 3D–3D | 三维点 | 三维点 | ICP/SVD | 两组点间刚体变换 |

表中的缩写先只做定位：PnP 是“由三维点到二维像素对应估位姿”；ICP 是“反复找点云对应并更新位姿”；SVD（Singular Value Decomposition，奇异值分解）是一种矩阵分解工具，可在已知三维对应时求刚体对齐。后文会依次解释，不要求现在记算法细节。

第一遍不要背算法名字。先问：

> 这批对应关系的两端，各自有没有深度？

## 2. 2D–2D：两边都只有像素

有匹配：

```text
(u_1, v_1) ↔ (u_2, v_2)
```

两端都只是二维像素，没有点的深度。这常发生在单目系统刚开始、地图尚未建立时。

### 2.1 同一空间点产生两条射线

使用相机内参把像素变为归一化方向：

```text
x_1 = K⁻¹ [u_1, v_1, 1]ᵀ
x_2 = K⁻¹ [u_2, v_2, 1]ᵀ
```

- `K`：相机内参矩阵；
- `x_1、x_2`：两个相机坐标系中的射线方向齐次表示。

存在未知深度 `Z_1、Z_2`，使同一空间点满足：

```text
Z_2 x_2 = R (Z_1 x_1) + t
```

- `R`：第一相机坐标到第二相机坐标的相对旋转；
- `t`：相对平移；
- `Z_1、Z_2`：该点在两帧中的未知深度。

问题是每对点都多出深度未知量。对极几何的作用，就是消掉这些逐点深度，先约束共同的相机运动。

## 3. 对极几何的直觉：第二个点不会出现在整张图任意位置

第一帧一个像素对应空间中一整条射线。把这条射线通过两个相机间的相对位姿投到第二张图，它会变成一条线，叫极线。

若匹配正确，第二帧像素应该落在这条极线上。

```text
第一帧一个点
      ↓ 对应一条空间射线
      ↓ 投到第二帧
第二帧的一条极线
```

因此 2D–2D 几何不是直接告诉你深度，而是把第二帧的搜索从整张二维图缩成一条一维线，并用许多对应共同约束相机运动。

## 4. 本质矩阵公式到底表达了什么

归一化坐标满足：

```text
x_2ᵀ E x_1 = 0
```

其中：

```text
E = [t]× R
```

- `E`：Essential Matrix，本质矩阵；
- `R`：两帧间相对旋转；
- `t`：相对平移；
- `[t]×`：由向量 `t` 构造的反对称矩阵，使 `[t]× a = t × a`；
- `×`：三维叉乘；
- 上标 `ᵀ`：转置。

这一标量等式等于零的几何含义是：

> 第一帧射线、第二帧射线和两个相机中心之间的平移，应该位于同一个对极平面内。

第一遍不必手推 `[t]×`。要知道 `E` 把相对旋转和平移方向压进一个能检查匹配几何一致性的矩阵。

如果想把“共面”到这条公式的每一步慢慢走一遍，可转入专题：[对极几何从零推导](对极几何从零推导-为什么一个点对应另一张图中的一条线.md)。第一次主线阅读也可以跳过，继续下一节不会断。

## 5. 基础矩阵和本质矩阵有什么区别

如果直接使用像素坐标：

```text
p_2ᵀ F p_1 = 0
```

- `p_1、p_2`：像素齐次坐标；
- `F`：Fundamental Matrix，基础矩阵。

`F` 同时包含相机内参和两帧几何。若已知内参：

```text
E = K_2ᵀ F K_1
```

因此可以粗略理解：

```text
F：在原始像素坐标里说对极约束
E：去掉内参后，在归一化相机坐标里说对极约束
```

## 6. 为什么 2D–2D 只能得到平移方向，得不到长度

本质矩阵中：

```text
E = [t]× R
```

如果把 `t` 乘任意正数 `s`，`E` 也只整体乘 `s`。而方程右边仍是零：

```text
x_2ᵀ (sE) x_1 = s × 0 = 0
```

所以图像几何可以判断相机向哪个方向平移，却无法只凭两张单目图知道平移了 0.1 米还是 1 米。

这正是上一章单目尺度不确定性的另一种表现。

## 7. 从 `E` 分解出 `R、t` 为什么还有多个候选

一个本质矩阵通常能分解出多组旋转和平移方向组合。物理上正确的一组应该让三角化后的场景点位于两个相机前方，这叫正深度检验。

因此过程不是：

```text
E → 唯一绝对真值
```

而是：

```text
匹配 → RANSAC 估 E → 分解出若干候选 R,t
     → 三角化并检查正深度 → 选合理候选
```

若相机几乎纯旋转、视差很小或场景退化，选择仍可能不稳定。

## 8. 单应矩阵：当场景近似一个平面

如果大量点都位于同一平面，或相机只发生旋转，两个图像之间可用 Homography（单应矩阵）`H` 描述：

```text
p_2 ∼ H p_1
```

符号 `∼` 表示齐次坐标只要求相差一个非零比例。

典型场景：

- 相机拍摄一张海报或地面；
- 远处场景且相机以旋转为主；
- 图像拼接。

初始化时常同时检查本质矩阵和单应矩阵。不是看到 `H` 内点多就一定成功，还要判断能否恢复出稳定、有足够视差的三维结构。

## 9. 2D–2D 的典型失败条件

- 纯旋转或平移太小：几乎没有三角化基线；
- 点都集中在小区域：约束方向单一；
- 大量点共面：模型可能退化或存在歧义；
- 重复纹理导致一致性错匹配；
- 动态物体主导画面；
- 镜头畸变或内参错误；
- 滚动快门下整帧并非单一刚体位姿。

2D–2D 更适合建立初始相对几何，不是每一帧都必须重复从零求本质矩阵。

## 10. 3D–2D：地图点已经有深度，当前帧只有像素

现在局部地图中已有三维点 `P_i` 的世界坐标 `p_w_i`，并在当前图像找到对应像素 `z_i = [u_i, v_i]ᵀ`。

问题变成：寻找当前相机位姿 `T_cw`，让地图点投影后尽量落在观测像素上：

```text
p_c_i = T_cw p_w_i
z_hat_i = project(K, p_c_i)
r_i = z_i - z_hat_i
```

- `project(...)`：第 03 章的相机投影；
- `z_hat_i`：当前位姿假设下预测像素；
- `z_i`：实际匹配像素；
- `r_i`：第 `i` 个点的重投影残差。

寻找使许多 `r_i` 都小的位姿，就是 PnP。

## 11. PnP 是什么

PnP 全称 Perspective-n-Point：已知 `n` 个三维点及其二维图像对应，估计相机位姿。

它非常适合持续视觉 SLAM：

```text
局部地图中已有三维点
      +
当前帧找到这些点的像素
      ↓
PnP + RANSAC 得到当前位姿候选
      ↓
重投影误差优化精化位姿
```

PnP 输出的是相机相对于三维点所在地图坐标系的位姿，因此地图若有米制尺度，位姿平移也有同样尺度。

### 11.1 为什么 PnP 仍需 RANSAC

3D 地图点到 2D 像素的关联可能错误。少数错关联能严重拉偏位姿，所以先用 PnP-RANSAC 找一致内点，再对内点进行非线性优化。

### 11.2 PnP 的失败条件

- 对应点太少；
- 三维点几何分布退化，例如几乎共线；
- 点都很远或集中在视野一角；
- 地图点本身位置很差；
- 初值太差、错匹配太多；
- 相机模型或畸变处理错误。

## 12. 3D–3D：两边都有三维坐标

若两帧都能获得深度，建立三维点对应：

```text
p_i ↔ q_i
```

希望找到 `R、t`，使：

```text
q_i ≈ R p_i + t
```

可以最小化：

```text
Σ ||q_i - (R p_i + t)||²
```

- `Σ`：把所有对应点的误差加起来；
- `||...||`：向量长度；
- 平方使正负误差不会抵消，并更重罚大误差。

若对应已知，可用 SVD 等方法求刚体变换；点云配准中常用 ICP 交替执行：

```text
根据当前位姿找对应
          ↓
根据对应更新位姿
          ↓
重新找对应并继续迭代
```

## 13. 点到点与点到平面误差

点到点 ICP 使用：

```text
r_i = q_i - (R p_i + t)
```

要求变换后的点靠近目标点。

点到平面 ICP 若知道目标局部平面法向 `n_i`，使用：

```text
r_i = n_iᵀ (R p_i + t - q_i)
```

它只惩罚沿平面法向的距离。点在平面切向稍微滑动不影响表面对齐，因此在表面密集点云中常收敛更快。

- `n_i`：目标点附近平面的单位法向量；
- `n_iᵀ v`：向量 `v` 在法向方向的投影长度。

## 14. ICP 为什么需要初值

ICP 中“最近点”由当前位姿决定。初值若太远，桌腿可能被配到墙上，然后算法在错误对应上继续优化。

因此常用 IMU、轮速、上一帧速度或粗特征给初值，再用 ICP 精细对齐。

ICP 是局部迭代方法，不是把任意两堆点扔进去就自动找到全球正确位置。

## 15. 三类方法其实都在做“预测—比较—修正”

### 2D–2D

```text
猜相对几何 → 预测对应点应满足哪条极线 → 看匹配是否一致 → 修正
```

### 3D–2D

```text
猜相机位姿 → 把地图点投到图像 → 与实际像素比较 → 修正
```

### 3D–3D

```text
猜刚体变换 → 把一组点变到另一坐标系 → 比较点/面距离 → 修正
```

输入维度不同，核心都是构造一个当前猜测下的预测，再利用残差调整未知位姿。

## 16. 当前帧为什么不总从头计算

持续系统已经有上一帧位姿、速度趋势和局部地图。它通常：

```text
用运动模型或 IMU 预测当前位姿
      ↓
在预测区域寻找地图点
      ↓
PnP/重投影或点云残差修正预测
```

好初值让搜索范围更小、匹配更可靠、非线性优化更容易收敛。所谓“跟踪”就是利用时间连续性，不把每一帧当作第一次看到世界。

## 17. 结果验收不能只看一个残差平均值

还应检查：

- 内点数量和内点比例；
- 特征是否覆盖图像或三维空间；
- 平移、转动和速度是否物理合理；
- 深度是否为正且分布合理；
- 模型是否退化；
- 优化前后残差是否正常下降；
- 与 IMU/轮速预测是否严重冲突；
- 连续帧结果是否突跳。

一个错误位姿可能恰好解释一小簇点，平均残差也很小，但它没有足够几何覆盖，不能代表整台相机的运动。

## 18. 本章最小结论

```text
2D–2D：两边都没有深度，用对极几何估相对旋转和平移方向
3D–2D：地图侧有三维、图像侧有二维，用 PnP 估当前相机位姿
3D–3D：两边都有三维，用点云/刚体配准估相对变换
```

所有方法都依赖正确数据关联，都可能退化，都输出需要验证的估计。
